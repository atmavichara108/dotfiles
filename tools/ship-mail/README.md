# ship-mail — почта Корабля (файловая шина)

Доставка письма = атомарная запись файла в ящик получателя. Ноль ходов модели,
ноль демонов, ноль журнала — файлы и есть истина, статус = место на диске.
«Потерянное письмо» невозможно по построению (write-once + ack).

## Регламент (канон Р-028)

1. **Первым шагом каждого хода сессии** — `ship-mail.sh inbox <свой sessionID>`; отработал письмо — `ship-mail.sh ack <sid> <файл|all>`.
2. Письма отправлять этим инструментом (`send`). Адресация — только через `peer-registry` (INC-18): оба конца в реестре, иначе отказ.
3. **peer-comms/letter.sh — в резерве** (deprecated): аврал, релей владельца, живая инжеккция хода модели. Снятие — совместным решением после стабилизации (Мастерская чинит его параллельно).

## Интерфейс

```
ship-mail.sh send --to SID --from SID [--title T] [--ref R] (--file F | --text MSG)
ship-mail.sh inbox <sid>          # непрочитанные: счёт + строки
ship-mail.sh show <sid> [файл]    # прочитать (без имени — все непрочитанные)
ship-mail.sh ack <sid> <файл|all> # принять: файл переезжает в read/
ship-mail.sh status <sid>         # unread/read
```

Коды: 0 ok · 1 usage · 2 нет файла · 3 дубль (идемпотентность: id=SHA-256(тело+отправитель+день)) · 4 адрес вне реестра · 5 реестра нет.

## Окружение

- `SHIP_MAIL_HOME` — корень ящиков (умолчание `~/.local/share/ship-mail`; `inbox/<sid>/`, `read/` внутри).
- `SHIP_MAIL_REGISTRY` — реестр адресов (умолчание волт `04-Memory/peer-registry.md`).

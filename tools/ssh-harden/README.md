# ssh-harden — экран SSH по мандату ЦУ (ic-ssh-harden, 2026-11-06)

Закрывает: вход только по ключу, корень-off, стойкость к перебору (MaxAuthTries),
явные настройки вместо defaults. Применение и откат — одним блоком команд.

## Факты на момент подготовки (сверено read-only 06.11 19:5x)

- sshd: `sshd.service` — **active (running), enabled**; Main PID 1084230 — тот же
  процесс, что висит на 0.0.0.0:22 и [::]:22. PPID=1 у системной службы — норма
  (демон переродитель systemd), **не** «процесс-сирота вне управления».
- `~/.ssh/authorized_keys` — 1 рабочий ключ (создан 06.11 16:24): перевод на
  ключ-only безопасен, запирания нет.
- `PasswordAuthentication` явно не задан нигде (default yes) → вход по паролю
  возможен; `PermitRootLogin` — default prohibit-password. Нужен явный `no`.
- `KbdInteractiveAuthentication no` уже в 99-archlinux.conf (страховка — в нашем
  drop-ине).
- `fail2ban` **не установлен** (не «выключен»): `pacman -Q fail2ban` — not found,
  служба not-found. Установка пакета — зона владельца (не ставим сами).

## Применение (команды, root)

```bash
cd ~/dotfiles
sudo bash tools/ssh-harden/apply.sh
```

Скрипт: проверит ключ (стоп, если его нет — kill-условие), сделает бэкап,
положит drop-ин, прогонит `sshd -t` (невалидно — авто-откат), reload sshd,
проверит отказ парольного входа и снимет listener'ы.

## Откат (команды, root)

```bash
cd ~/dotfiles
sudo bash tools/ssh-harden/rollback.sh
```

Удаляет drop-ин, валидирует, перезапускает sshd. Прежний drop-ин (если был)
сохраняется копией при применении; если не был — прежнее состояние = дефолты.

## Остаток по мандату

- Критерий «страж перебора включён локально»: fail2ban не установлен — установка
  пакета требует слова владельца (зона пакетов). До install'а перебор
  ограничивается MaxAuthTries; полноценный сторож — отдельное решение.

# peer-comms

## Письма — ОТКЛЮЧЕНО (2026-11-06)
Почта Корабля — только `../ship-mail/ship-mail.sh` (канон Р-028): письмо =
файл `type: Letter` в ящике получателя, чтение первым шагом хода, ack после
отработки. Старый канал `letter.sh` («простыни») вызвал ложные «молчания»
отделов и зависания очереди — отключён совсем, exit 5. Старые хвосты
архивируются с пометкой, не удаляются. Новые письма этим каналом не
принимаются.

## session-model-set.sh — смена модели сессии ТОЛЬКО с доказательством

```
session-model-set.sh <sessionID> <providerID>/<modelID>
```

**Канон (урок инцидента inc-silent-success-20261025):** POST
`/api/session/<id>/model` отвечает **пустым выводом с кодом 0** — «пустой
ответ + exit 0» агенты принимали за успех и рапортовали «модель переключена»
без доказательства. Поэтому:

1. **Прямой вызов api POST смены модели без read-back запрещён** — только
   через обёртку `session-model-set.sh`.
2. Обёртка: POST → ОБЯЗАТЕЛЬНЫЙ GET `/api/session/<id>` → сравнение
   provider+model → exit 0 **только при совпадении**, иначе exit 1 с печатью
   «хотел/стало».
3. Класс-правило для любого state-change с пустым ответом: команда обязана
   завершаться чтением состояния назад в той же строке.

Тесты: идемпотентный вызов текущей модели → OK (read-back); неверный формат →
отказ; несуществующая сессия → отказ по HTTP. Опасное (проверено на живом
инциденте): POST принимает даже несуществующую модель — read-back это и
ловит.

## Опасный эксперимент — только не на живой сессии
Смена модели живой сессии на заведомо несуществующую ломает ход (модель
недоступна). Восстановление — та же обёртка с правильной моделью. Любые
тесты переключения — на одноразовых сессиях или уже сломанных, не на боевых.

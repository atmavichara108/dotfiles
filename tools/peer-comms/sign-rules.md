# Правила знаков канала

Пять правил — канон любого письма/сообщения в Корабле. Нарушение = инцидент
канала, не «мелочь».

1. **После фазы.** Статус письма — только после свершения события. Иначе —
   другое слово (queued/sent ≠ delivered/processed).
2. **Референт снаружи.** Доказательство доставки — след у **получателя**
   (прочитано/обработано), не журнал отправителя. Журнал отправителя —
   заявка, не доказательство.
3. **Один адрес.** id сессии берём программно из канонического реестра
   (peer-registry), не из текста письма или памяти.
4. **Фантом не рождается.** Несуществующий id → отказ **до отправки**
   (INC-18).
5. **Квитанция ≠ обработка.** delivered и processed — разные события
   (INC-17). `sent` в журнале при непрочитанном письме — инцидент (INC-21).

## Дрейф-детектор (три оси, в session-cop + watch-logs)

1. **Канал:** sent/queued без delivered/processed у получателя → дрейф.
2. **Claims:** активные claims вне peer-registry → дрейф.
3. **Имена:** имя файла inbox vs программно извлечённый frontmatter from →
   дрейф.

Базовая эмпирика (школа, 2026-10-30): sent 411 vs delivered 7, timeout 105,
failed 18, dead-letter 2.

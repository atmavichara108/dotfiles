# Goal — автономное доведение до результата

OpenCode 2.2.1+ поддерживает `/goal <objective>`: сессия продолжает работать
автономно, пока рецензент не подтвердит, что цель достигнута.

## Хранилище

Цель хранится в `~/.local/state/opencode/goal.json` (переживает ходы и компакт).

## Поля цели

- **objective** — дословный текст владельца (basis: quoted)
- **criteria** — проверяемые критерии (числа, файлы, тесты, HTTP-коды)
- **kill** — условие останова (что считать провалом)
- **wip** — «один активный» (нельзя иметь две цели одновременно)
- **status** — active / paused / done / dropped
- **evidence** — факты достижения (append-only)

## Команды

- `/goal <текст>` — поставить цель (запросит criteria и kill, если не указаны)
- `/goal show` — показать текущую цель
- `/goal done` — закрыть как достигнутую (проверка критериев + evidence)
- `/goal drop` — отменить цель (с причиной)
- `/goal pause` / `/goal resume` — приостановить/возобновить

## Сайдкар и общая цель (Р-042 / Р-044)

Один `goal.json` на все сессии больше не единственный механизм:

- **Сайдкар на сессию** (Р-042): `~/.local/state/opencode/goals/<sid>.json` —
  у каждой сессии своя цель, перезаписи цели другой сессии не происходит.
  Порядок: ставить сайдкар, когда цель именно сессионная; агрегат
  `goal.json` — для одной общей цели ведомства.
- **Общая цель на несколько ведомств** (Р-044): `goal.py share <slug>` создаёт
  `goals/goal-<slug>.json` — цель-объект с участниками; участники входят
  `goal.py join <slug> --session <sid>`, вклад пишут `goal.py contrib <slug>
  --session <sid> --evidence ...`, сводку «кто что сделал» даёт `goal.py shared`.
  Slug в `shared` опционален (без него — все цели).
  Сигнал молчания участника (TTL) — бесшумный, не повод для писем.
- Автор цели (`--session` создателя) единственный правит критерии: правка
  `criteria` — всегда автором, иначе второй хозяин данных (правило одного
  хозяина). Участник правку просит письмом, не правит сам.

Правило каждого хода действует для обоих типов: активная сайдкар-цель или
участие в общей цели обязывают проверять критерии на каждом ходе.

## Когда ставить /goal

1. **Многошаговые задачи** (3+ шагов): фикс → проверка → коммит → выкладка.
2. **Задачи с проверкой результата**: «модель отвечает ok», «тесты проходят», «дерево чистое».
3. **Восстановление после сбоев**: EOL модели, отказ провайдера, поломка канала.
4. **Доставка секретов**: форма → файл → проверка → коммит.

## Когда НЕ ставить /goal

- Одиночный вопрос/ответ (без действий).
- Задача требует решения владельца (выбор модели, подтверждение плана).
- Задача с неясным scope (сначала уточнить).

## Как формулировать цель

Цель должна быть **проверяемой** (рецензент может подтвердить):

- ✅ `/goal verifier и obsidian-servant работают на новых моделях, EOL-модели убраны из всех конфигов, коммит сделан`
- ✅ `/goal apinex: ключ доставлен в ~/.secrets, environment.d собран, модель отвечает ok`
- ✅ `/goal дерево чистое, main == origin/main, новая ветка создана`
- ❌ `/goal починить NVIDIA` (непроверяемо — что значит «починить»?)

## /goal show — критерии с отметкой «проверено как?»

Каждый критерий печатается с полем evidence («проверено как?»), чтобы
проверка /goal done была не в голове агента, а в выводе:

```
Цель: <objective>
Критерии:
  1. <критерий> — проверено: <evidence или «не проверено»>
```

## Правило каждого хода (автоматическое)

Если в `~/.local/state/opencode/goal.json` есть цель со `status: "active"`:
1. **Напоминание:** в начале хода агент обязан учитывать активную цель.
2. **Проверка:** каждый ход — проверить, достигнута ли цель по критериям.
3. Если цель достигнута — предложить `/goal done`.
4. Если kill-условие сработало — предложить `/goal drop`.

## Правила

1. Цель — одна, конкретная, с критерием успеха (wip: один активный).
2. Если цель требует подтверждения владельца (выбор, секрет) — сначала получить ответ, потом ставить /goal.
3. При паузе/отмене — зафиксировать причину в память (decisions.md).
4. Не ставить /goal для задач, которые уже в процессе — только для новых.
5. Гейты владельца не ослаблять: цель ставится только по явному указанию владельца.

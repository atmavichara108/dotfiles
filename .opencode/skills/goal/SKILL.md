# Goal — автономное доведение до результата

OpenCode 2.2.1+ поддерживает `/goal <objective>`: сессия продолжает работать
автономно, пока рецензент не подтвердит, что цель достигнута.

## Команды

- `/goal <objective>` — поставить цель, сессия работает до подтверждения
- `/goal pause` — приостановить
- `/goal resume` — возобновить
- `/goal clear` — отменить

## Когда ставить /goal

1. **Многошаговые задачи** (3+ шагов): фикс → проверка → коммит → выкладка.
2. **Задачи с проверкой результата**: «модель отвечает ok», «тесты проходят», «дерево чистое».
3. **Восстановление после сбоев**: EOL модели, отказ провайдера, поломка канала.
4. **Доставка секретов**: форма → файл → проверка → коммит.

## Когда НЕ ставить /goal

- Одиночный вопрос/ответ (без действий).
- Задача требует решения владельца (выбор модели, подтверждение плана).
- Задача с неясным scope (сначала уточнить).

## Как формулировать цель

Цель должна быть **проверяемой** (рецензент может подтвердить):

- ✅ `/goal verifier и obsidian-servant работают на новых моделях, EOL-модели убраны из всех конфигов, коммит сделан`
- ✅ `/goal apinex: ключ доставлен в ~/.secrets, environment.d собран, модель отвечает ok`
- ✅ `/goal дерево чистое, main == origin/main, новая ветка создана`
- ❌ `/goal починить NVIDIA` (непроверяемо — что значит «починить»?)

## Правила

1. Цель — одна, конкретная, с критерием успеха.
2. Если цель требует подтверждения владельца (выбор, секрет) — сначала получить ответ, потом ставить /goal.
3. При паузе/отмене — зафиксировать причину в память (decisions.md).
4. Не ставить /goal для задач, которые уже в процессе — только для новых.

# Letters Communication — письма-коммуникации

Правило закреплено **программно** (не «совестью агентов»):

| Слой | Что принуждает |
|------|----------------|
| `tools/ship-mail/lint_letter.py` | линт-гейт письма перед отправкой: FAIL блокирует, WARN допустимы (Р-090) |
| `tools/ship-mail/ship-mail.sh` | доставка атомарным файлом; адресация только через peer-registry (INC-18) |
| `tools/ship-mail/waits.py` | связка письма с открытым ожиданием (реф/пришивка) |

## Формат письма (Р-090)

Письмо обязано содержать, иначе FAIL:

1. **Заголовки** `type`, `from`, `to`, `title`, `ref` (from/to — полные sessionID вида `ses_...`).
   `ts` линтом не проверяется (добавляется транспортом), но желателен для следа.
2. **ref уникален** — не повторяет ранее отправленное (журнал `sent.jsonl`).
3. **Три раздела**: `СДЕЛАНО`, `ЗАБЛОКИРОВАНО`, `ЖДЁТ` (линт требует наличие этих маркеров).
4. **Если письмо несёт действие** (мандат/прошу/сделай/задача/проверь и т.п.) — оканчивается фразой
   `после выполнения … продолжаю …` (маркер `CONTINUE_RE`).
5. Мандат-номер регистрируется только явным объявлением (`мандат: Р-N`), иначе ссылка «Р-N» — не регистрация.

WARN (не блокер): sha256 без пути; ссылка на локальный путь, которого нет на диске.

## Поток отправки

1. Напиши письмо в файл (через `--file`/`--stdin`).
2. Прогони линт-гейт с заголовками как флагами:
   `lint_letter.py --file <письмо> --type Letter --title <t> --ref <r> --from <sid> --to <sid>`
   — получи LINT PASS (или WARN, но не FAIL). (ship-mail.sh сам вызывает lint с флагами при `send`.)
3. Отправь: `ship-mail.sh send --to <sid> --from <sid> --title <t> --ref <r> --file <path>`.
   Адрес получателя — ТОЛЬКО из peer-registry (INC-18), не из чата.
4. Получатель отвечает `ack` (перенос в read/); отправитель может проверить доставку.

## Когда использовать

- Любая отправка письма между сессиями/ведомствами Корабля.
- Ответ на мандат/перекличку/отчёт.
- Согласование решений, передача мандатов.

## Когда НЕ использовать

- Сообщения владельцу через Ворота (owner-gate MCP-формы) — отдельный канал.
- Внутрисессионные заметки (не письма).

## Запреты

- Отправлять письмо без прохождения lint-гейта (FAIL).
- Адресовать по sessionID из чата, минуя peer-registry (INC-18).
- Дублировать ref (уникальность обязательна).
- Письмо с действием без фразы «после выполнения … продолжаю».

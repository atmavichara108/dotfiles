# Parallel Sessions — координация параллельных сессий

Правило закреплено **программно** (не «совестью агентов»):

| Слой | Что принуждает |
|------|----------------|
| `tools/ship-mail/ship-mail.sh` | единственный транспорт писем; адресация только через peer-registry (INC-18) |
| `plugins/tree-hygiene.ts` + `githooks/pre-commit` | чистое дерево, одна task-ветка = один сюжет |
| `tools/ship-mail/waits.py` | реестр ожиданий: TTL, пинки, дедлайны |
| `tools/ship-mail/wake.py --sweep` | автопинг просроченных + зов живых линий |

## Правила

1. **Inbox-first:** первый шаг хода — `ship-mail.sh inbox <свой sid>`; отработал письмо — `ack`.
2. **Ожидание = реестр:** «жду X от Y» → `waits.py add` с TTL и дедлайном; просрочка пингуется автоматически (autoping), не дисциплиной.
3. **Автоповещение:** завершил чужую задачу → рапорт инициатору в том же ходе; висячие ожидания — дефект.
4. **Письмо с требованием действия** оканчивается «после выполнения — продолжай работу»; ответ на письмо — не конец хода (Р-088/Р-089).
5. **Работай до результата** (Р-122): пока есть нерешённые задачи — ход не заканчивается докладом о планах.
6. **Чужие незакоммиченные правки** — через tree-cop (`stash-foreign`), не вопросы к владельцу и не молчаливые коммиты.
7. **Доставлено ≠ прочитано:** ящик — не голова адресата; зов живой линии идёт независимо от свежести read (fix 89b1cb2), мёртвых не зовём (preflight 404).

## Поток координации

1. Задача из другой сессии → `started`/ack → работа → `finished` с артефактом/SHA → рапорт инициатору.
2. Ждёшь от другой линии → `waits.py add` → дальше работаешь свои задачи; пинг придёт автоматически.
3. Конфликт веток/дерева → tree-cop, не ручные разборы.

## Когда НЕ использовать

- Одиночная сессия без внешних постановок и ожиданий.
- Мгновенные действия ритуала (ack/чтение) без ожиданий.

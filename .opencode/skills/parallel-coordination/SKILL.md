# Parallel Coordination — координация параллельных сессий

Правило закреплено **программно** (не «совестью агентов»):

| Слой | Что принуждает |
|------|----------------|
| `tools/ship-mail/ship-mail.sh` | файловая шина почты: первый шаг хода — `inbox`, письмо — атомарный файл, ack = прочитано |
| `tools/ship-mail/waits.py` | реестр открытых ожиданий (TTL, пинок, дедлайн); прострочка — пинок, не дефект, дедлайн в what |
| `tools/ship-mail/persist.py` | запись важного на диск до ответа (Р-105): слово владельца, решение, ожидание, evidence |
| `plugins/session-flush.ts` | при смене состояния сессии дописывает список изменённых файлов в `04-Memory/session-log/`; снимок/хеш при смене модели/передаче мандата — `persist.py flush` (Р-105) |
| `plugins/bugfix-capture.ts` | захват сбоев инструментов/провайдеров/прав в реестр `~/.local/state/opencode/incidents/` |

## Правила

1. **Первый шаг хода — почта и ожидания.** `ship-mail.sh inbox <sid>` + `waits`
   — что открыто у меня и от меня. Отработал письмо — `ack` (по имени файла).
2. **Отправка — только через `ship-mail.sh send`** (адресация через peer-registry,
   INC-18: id из чата не каноничен). Формат письма: СДЕЛАНО / ЗАБЛОКИРОВАНО / ЖДЁТ
   + «после выполнения … продолжаю» в конце (линт).
3. **Открытые ожидания не застаиваются.** `waits.py` ведёт TTL: прострочка —
   пинок (не дефект), дедлайн — в what. Отвечающий закрывает ожидание письмом.
4. **Важное — на диск ДО ответа** (Р-105): слово владельца (дословно, basis: quoted),
   решение, ожидание, evidence — через `persist.py write`. Сжатие/смена модели не
   забирает единственную копию.
5. **Сбой — на багфикс на лету**: bugfix-capture ловит сбои, записывает в реестр.
   Повторяющуюся недиагностированную ошибку — `/bugfix`.
6. **Смена модели/передача мандата — флеш** (`persist.py flush`): снимок + хеш.
   Экран/зеркало, где печать ≠ пересчёт, — дефект.

## Поток хода

1. `ship-mail.sh inbox <sid>` — читать письма; `ack` каждое после отработки.
2. `waits` — открытые ожидания (свои и чужие от меня).
3. `persist.py check` — свежесть записи (>15 мин — пиши заново).
4. Работа.
5. Важное — `persist.py write`.
6. Письма/ожидания — закрыть (ack / ответ по waits).
7. Передал мандат/сменил модель — `persist.py flush`.

## Когда использовать

- Общее репо с параллельными сессиями (dotfiles, волт, serp и т.д.).
- Передача мандатов, автоповещение инициатору о завершении.
- Восстановление после сбоя канала/модели.
- Сложные многошаговые задачи (см. также /goal).

## Когда НЕ использовать

- Изолированная разовая задача без других сессий.
- Мгновенные действия ритуала (без почты/ожиданий).

## Запреты

- Первый шаг хода без `inbox` (пропустил почту/ожидания).
- Отправка не через `ship-mail.sh` (в обход шины/реестра).
- Открытое ожидание без дедлайна или повисшее навсегда.
- Важное слово владельца только в контексте (без записи на диск).

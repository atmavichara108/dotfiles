# Инцидент: агент пропадает из реестра после перечитывания конфигов

## Симптом

`task(agent="researcher")` возвращает ошибку `Unknown agent: researcher`
(tool.execution), при этом:

- файл `opencode-global/.config/opencode/agent/researcher.md` на месте;
- фронтматтер валиден строгим YAML (pyyaml), дублей ключей нет;
- модель `opencode-go/glm-5.3-flash` проверена инструментом моделей — **существует,
  status=active**;
- блоки `agent`/`agents` из проектного `opencode.json` удалены осознанно (И-07),
  канон — `.md`.

## Контекст

Сессия `ses_ece7b76c8ffeOkYZqZe38QbTVx`. Движок opencode v2.0.26. Служба
`opencode serve --service` (pid 3803212, старт 00:53), TUI (pid 3802103, старт 00:53).
Перед сбоем в `.../agent/researcher.md` шли правки прав в несколько заходов
(сначала потеря правил при сведении к `.md`, затем восстановление по вердикту
`verifier`).

## Воспроизведение

1. Изменить `opencode-global/.config/opencode/agent/researcher.md`.
2. Рантайм сообщает «конфиги сессии менялись» и перечитывает определения.
3. Немедленный `task(agent="researcher")` → `Unknown agent: researcher`.

При этом `task(agent="verifier")` в том же окне времени проходит успешно — то
есть выпал конкретный агент, а не весь реестр.

## Корневая причина (гипотеза, не подтверждена)

Перечитывание «на лету» застало файл в промежуточном состоянии (правки шли
несколькими записями подряд) и удалило определение агента из реестра, не вернув
его после исправления. Прямой причины в логах не найдено: лог агентов не пишет
события регистрации.

**Не подтверждено:** нужен чистый рестарт и повторный прогон, чтобы сказать,
дефект это или транзиентное состояние гонки.

## Обход

Полный перезапуск службы и TUI: реестр строится с диска заново. Есть штатный
биндинг `service.restart` = `<leader>shift+r`.

## Фикс

1. После рестарта проверить, что `researcher` снова распознаётся (`task` на
   минимальной задаче).
2. Если воспроизводится — это дефект перечитывания конфигов: оформить как
   отдельный пункт (правило: правки агентских `.md` делать атомарно, одной
   записью, и завершать волну рестартом — уже записано в `orchestration.md`).

## Статус

`closed`. Финальная приёмка `verifier`: PASS (все пять проверок). Агент в реестре (19 позиций, независимое подтверждение через `opencode debug agents`), правила не потеряны (83=83=83), все 13 агентских .md проходят усиленный чекер.

## ОБНОВЛЕНИЕ (после перезапуска): причина найдена, гипотеза опровергнута

Гипотеза «гонка при перечитывании конфигов» **не подтвердилась**: агент не вернулся
и после полного перезапуска — то есть определение отклонялось при каждой загрузке.

**Настоящая причина:** в блоке прав `researcher.md` были **дубликаты ключей YAML**
(13 повторов: `"basename*"`, `"dirname*"`, `"tokei*"`, `"procs*"`, `"date*"`,
`"md5sum*"`, `"sha1sum*"`, `"sort*"`, `"uniq*"`, `"cut*"`, `"jq*"`,
`"sqlite3 -readonly *"`, `"python3 -m json.tool*"`). Они появились при добавлении
read-only шаблонов (И-06): часть паттернов уже была в файле ниже. Строгий YAML на
дубликате падает → рантайм отклоняет определение целиком → `Unknown agent`.
Маскировалось тем, что раньше агент приходил из проектного `opencode.json`; после
сведения к канону `.md` стал единственным источником — и дефект вышел наружу.

**Почему не поймали раньше:** проверка использовала `yaml.safe_load`, а он
дубликаты **молча проглатывает** (берёт последний) → ложный PASS.

**Фикс:** дубликаты удалены с приоритетом строгости `deny > ask > allow`
(96 → 83 строки, потерянных правил — 0). Строгий валидатор с детекцией дублей
положен в репозиторий: `tools/agent-yaml-check.py`. Все 13 агентских `.md`
проходят проверку.

**Урок:** конфиги агентов валидировать только строгим парсером; ошибка в одном
файле делает агента **невидимым**, а не «сломанным», и диагностируется как
`Unknown agent`.

## ПРИЧИНА НАЙДЕНА ОКОНЧАТЕЛЬНО — двухслойная

1. **Слой 1 (И-06).** При добавлении read-only шаблонов в блок прав попали
   **дубликаты ключей YAML** (13 повторов). Строгий парсер падал → движок
   отбрасывал определение агента целиком.
2. **Слой 2 (мой фикс дубликатов).** Скрипт дедупликации убрал дубликаты, но
   добавил **хвостовые запятые** в значения (`deny,`, `allow,`, `ask,`). В
   блочном YAML запятая становится **частью строки**, то есть эффект делается
   недопустимым. pyyaml принимает `"deny,"` как валидную строку — поэтому мой
   чекер молчал, а движок продолжал отбраковывать агента.

Итого агент выпадал по двум разным причинам последовательно; зарегистрировался
только после устранения запятых.

## Как нашли (метод, который стоит повторять)

- `opencode service restart` + `opencode debug agents` — реестр читается с диска,
  это и есть надёжный тест регистрации (в отличие от проверки по файлу);
- бисекция блока прав: минимальное определение под тем же именем регистрировалось
  (значит имя свободно, дело в содержимом), блок прав, заменённый одной строкой,
  регистрировался (значит виноват блок правил), срез `[0:42]` — нет;
- независимо то же самое нашла приёмка `verifier`, программно.

## Фикс

Хвостовые запятые убраны (83 правила, значения ровно `allow`/`deny`/`ask`,
дефолт `deny`); агент проверен живым вызовом (`ОК`). Чекер
`tools/agent-yaml-check.py` усилен: ловит **три** класса дефектов — дубликаты
ключей, недопустимые значения эффектов, хвостовые запятые.

## Урок

Проверять не только структуру конфига, но и **значения**; агентские `.md` править
парсером, а не склейкой строк; любое изменение определения агента заверять
**живой пробой** (`opencode debug agents` / вызов `task`), а не только проверкой
файла.

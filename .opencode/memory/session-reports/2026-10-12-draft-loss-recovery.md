# Инцидент: утрата неотправленного текста в поле ввода opencode TUI V2

Сессия: `ses_ece7b76c8ffeOkYZqZe38QbTVx` («Инженерный центр и параллельные лаборатории»).
Машина: Ecommunity108 (Manjaro, Qtile, Alacritty, tmux).

## Симптом

Дважды за одну сессию (2026-10-12, ориентировочно 22:20 и 22:40 MSK) пропал
неотправленный многострочный текст из поля ввода:

1. Пользователь писал длинное сообщение ~10+ минут, нажал `Ctrl+C` — текст
   исчез, приложение осталось живым.
2. Отдельно: отправленное сообщение пришло в сессию **усечённым с начала** —
   сохранённый текст начинался с середины фразы («…его что с ним связанно —
   найти что можно использовать практически в нашем Вайбе»), то есть начало
   не покинуло клиент.

## Воспроизведение

1. Набрать многострочный текст в поле ввода, не отправлять.
2. Нажать `Ctrl+C`. Текст исчезает **необратимо**; приложение не завершается
   (по аудиту хоткеев V2 `Ctrl+C` числится как «выход», фактически при
   непустом поле срабатывает как сброс без подтверждения).

Для второго проявления шаг 2 не нужен: достаточно длинного текста, отправка
уходит усечённой.

## Корневая причина

Черновик поля ввода живёт **только в памяти процесса клиента TUI** (куча
рантайма). Ни на одном шаге он не сохраняется на диск. Проверено адресно:

| Место | Результат |
|---|---|
| `~/.local/state/opencode/prompt-history.jsonl` | 50 записей — только **отправленные** промпты |
| `opencode.db` → `session_message` | типы `assistant/user/idle/system/synthetic/…`; типа `draft` **не существует** |
| `opencode.db` → `session_pending` | пусто |
| `opencode.db` → `part` | свежайшая запись — 2026-09-27 (V1-наследие) |
| `~/.local/state/opencode/latest/tui/*`, `kv.json` | только вкладки, тема, настройки |
| Скроллбек tmux | панель держит один экран (альтернативный буфер), кадры не сохраняются |
| Буфер обмена (copyq, 200 записей) | черновика нет: `Ctrl+C` ничего не копирует |

Итог: сброс поля = превращение строки в мусор сборщика мусора. Восстановление
из «снимков» невозможно по построению — восстановимого хранилища нет.

## Улика и восстановление

Восстановление выполнено чтением **живой памяти процесса TUI**, без остановки
процесса и без полного дампа на диск:

- цель: PID 1144760 (`opencode`, панель tmux `pb-dotfiles:3.1`, `/dev/pts/21`);
- метод: карта регионов `/proc/<pid>/maps` + присутствующие страницы
  `/proc/<pid>/pagemap` + чтение `process_vm_readv`; поиск цепочек UTF-16LE
  (кириллица) — так JS-строки лежат в куче рантайма;
- инструмент: `/tmp/opencode/memscan.py` (самотест на подставной цели; режим
  разбора дампа; расширенный режим со свопом и приватными сегментами);
- объём: обход 452 регионов, прочитано **757,6 МиБ** за 232 с, найдено
  2085 цепочек-кандидатов;
- отсев знакомого: собрано 394 МиБ текста из **всех** сессий базы
  (`session_message`), сравнение прямым поиском подстроки;
- результат: 83 новые цепочки, среди них **оба утраченных текста** —
  побайтово, в `docs/handoffs/2026-10-12-recovered-drafts.md`.

Права: чтение чужого процесса требует root. У `sysop` `sudo` закрыт жёстким
`deny` в глобальном конфиге; использован разовый запуск пользователем
(осознанное исключение из правила «primary не просит выполнять команды»:
альтернатива — постоянное ослабление гейта, что хуже).

## Фикс

Требуется (поручено `meta`, идёт отдельно):

1. Убрать у `Ctrl+C` возможность необратимо срезать черновик
   (биндинги живут в `~/.config/opencode/cli.json`; в репозитории файл
   внесён в `.gitignore` пакета `opencode-global` — решение о способе
   фиксации за `meta`).
2. Автосохранение черновика поля ввода (если V2 не даёт хука на ввод —
   зафиксировать это как `BLOCKED` и предложить ближайшую замену:
   внешний редактор промпта / сохранение перед отправкой).
3. Проверить второе проявление — усечение длинного текста при отправке.

## Статус

`open` — восстановление сделано полное (оба текста), фикс не применён.

## Что предотвратить впредь

- Длинный текст писать не в поле ввода, а в файл (Neovim), вставлять в TUI.
- Отправлять раньше, чем чистить: отправленное сохраняется в
  `prompt-history.jsonl` и в базе, неотправленное — нигде.
- Не считать «перезагрузку» и «отмену» безопасными: у `Ctrl+C` в этой сборке
  нет подтверждения на разрушительное действие.

# Пайплайн: задача (регистрация с двойным именованием)

## Смысл

Каждый нумерованный объект экосистемы (задача, резолюция, инцидент, этап) носит
**два имени** везде, где текст читается человеком: индекс + тип-имя в кавычках.

Канон утверждён владельцем 2026-10-20 — ADR-032, резолюция «двойное именование
объектов» (пленум ИЦ×ИПТ×ЦУ, все «за»).

## Шаги

1. Вход: `$ARGUMENTS` — суть задачи (от владельца — дословно, basis: quoted).
2. Прочитать реестр задач `.opencode/memory/inbox.md` (таблица
   `| ID | Позиция | Отсек | Владелец | Статус |`): найти последний T-индекс,
   взять следующий свободный. Индекс не переиспользуется и не пропускается.
   После добавления строки перечитать реестр и убедиться в единственности
   индекса (анти-коллизия параллельных записей).
3. Сформулировать двойное имя — единый формат пары: `<индекс> — <тип> «<имя>»`.
   Тип — из ЗАКРЫТОГО словаря (ADR-032): операция (задачи, BF-багфиксы),
   резолюция (ADR), решение (Р-серия — отдельный тип, не синоним резолюции),
   инцидент (INC), этап (волны/фазы), исследование (И-серия), метод (М-серия).
   Правило минимальности: тип существует только для реально пронумерованных
   классов с реестром; спеки, брифы и рефки писем не типизируются.
   Имя присваивается при рождении; смена — только по слову владельца.
   Имя берётся из слов владельца (basis: quoted); если имя не выражено его
   словами — предложи ему на утверждение ДО записи, не называй молча.
4. Добавить одну строку в таблицу реестра:
   `| <T-XXX> | операция «<имя>»: <суть> | <отсек> | <владелец> | <статус> |`.
   Один источник: только эта строка, без дублей в других файлах.
   Для задач от владельца в строке — ссылка на источник слова (ref письма
   или сессии): имя без референса на контекст — материал для дрейфа.
5. Ответить в чат одной строкой: `<T-XXX> — операция «<имя>» — заведена`
   (реестр: `.opencode/memory/inbox.md`).
6. Если запрос от владельца — в строке реестра пометка «слово владельца,
   basis: quoted» с ref источника.

## Гейты

- Индекс не переиспользуется; имена не меняются молча (только по слову владельца).
- Секреты в реестре запрещены.
- Реестр недоступен/конфликтен — BLOCKED с докладом, не молча.
- Коммит реестра — отдельный `docs(memory)`-коммит в своей task-ветке (zone-гейт).

# /resume — восстановление упавших субагентов

Дочерние сессии субагентов персистентны (БД сервера) и переживают рестарты.
Упавшая (outcome=failed) или прерванная (outcome=interrupted) сессия — НЕ
потерянная работа: исходное задание и весь контекст сохранены. Продолжение —
через прямой API-prompt в сессию (как TUI при сообщении в старую сессию).

ВАЖНО: subagent tool с sessionID продолжает ТОЛЬКО детей текущей сессии
(«not a child of the current session» для чужих). Поэтому основной путь —
API-prompt: он работает для любой сессии проекта.

## Пайплайн

1. Определи субагентские агенты: `opencode api get /api/agent` → собери
   `id` всех записей, у которых `mode == "subagent"`.
2. Список сессий: `opencode api get /api/session` → массив `data`.
3. Фильтр кандидатов:
   - `outcome` ∈ {`failed`, `interrupted`};
   - `agent` ∈ субагентские id из шага 1;
   - `location.directory` == текущий рабочий каталог.
4. Для каждого кандидата прочитай задание и родителя:
   - `opencode api get /api/session/{sessionID}/message` → последнее
     `type: "user"`-сообщение, поле `text` (начало = исходное задание);
   - `opencode api get /api/session/{sessionID}` → `parentID` (чья была
     работа; для context поясни пользователю).
5. Покажи пользователю таблицу: sessionID (первые 12 символов), agent,
   title, outcome, время падения (`time.updated`), задание одной строкой.
   Сортировка: свежие сверху.
6. Спроси, какие продолжать. `interrupted` может быть намеренным (Esc) —
   молчаливое продолжение запрещено. Если `$ARGUMENTS` == "all" — пропусти
   вопрос и продолжай всех кандидатов.
7. Для каждого подтверждённого:
   a. Отправь продолжение:
      `opencode api post /api/session/{sessionID}/prompt --data '{"text":"Продолжай выполнение прерванного задания с места остановки. Исходное задание и весь контекст уже в этой сессии — не начинай с нуля и не запрашивай задание заново. Если работа к моменту падения фактически завершена (или её объект исчез) — просто выдай финальный результат по исходной задаче."}'`
   b. Полли ответ: `opencode api get /api/session/{sessionID}/message`
      каждые ~30 сек, до `assistant` с `finish` ∈ {`stop`, ""} + запись
      `idle` сверху списка (список отсортирован новые-сверху).
   c. Если ответ упал с `finish=error` + `error.type=provider.quota` —
      штатный fallback: переключи модель сессии на модель текущего primary:
      `opencode api post /api/session/{sessionID}/model --data '{"model":{"providerID":"<provider текущего primary>","id":"<id модели текущего primary>"}}'`
      и повтори шаг 7a. Не более 2 повторов суммарно.
   d. Прочитай финальный текст ответа (первый `assistant` без
      `tool-calls`/`error`: поле `content[].text`) и включи его в отчёт.
8. Итог одним абзацем: кого продолжил, что вернул каждый, что отложено.

## Границы

- Только текущий проект (по `location.directory`) — чужие проекты не трогаем.
- Упавшие primary-сессии через этот путь не продолжаются: если попались —
  перечисли их отдельной строкой, пользователь откроет их в TUI сам.
- Если кандидатов нет — ответь одной строкой: «Упавших субагентских сессий
  в этом проекте нет».
- Никаких новых задач в упавших сессиях не ставь — только продолжение.
- Результат продолжения принадлежит той сессии: в свой контекст вставляй
  только итоговый текст, не пересылай всю переписку.

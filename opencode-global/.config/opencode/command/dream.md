# /dream — глобальная дистилляция и фиксация знаний сессии

Глубокая дистилляция завершённого обсуждения: не срочный сброс контекста,
а осмысленное структурирование — что решили, что переносимо в другие
сессии, чему научились, что дальше. Команда глобальная: работает из любого
проекта, исполняется в текущем агенте, без привязки к проектному агенту.

## Отличие от /flush

- `/flush` — срочное сохранение значимого контекста ДО компакции (окно
  контекста — RAM, не диск): быстро зафиксировать, чтобы не потерять.
- `/dream` — глубокая дистилляция/структурирование ПОСЛЕ завершения
  обсуждения: решения, новые reusable patterns, lessons, confirmed facts
  vs proposals/open questions, следующий actionable focus.
- Обе пишут в одну модель памяти проекта. `/dream` не дублирует то, что
  `/flush` уже записал — сначала читай существующие записи.

## Контекст
!`git log --oneline -5 2>/dev/null`
!`ls -d .opencode/memory docs/decisions.md 04-Memory 2>/dev/null`

Если вывод пуст — проверь пути своими read-only инструментами (read/glob).

## Задача

1. Определи project root (git root от cwd; если не git-репозиторий — cwd) и
   модель памяти проекта:
   - `.opencode/memory/decisions.md` — project-memory модель;
   - `docs/decisions.md` (и `docs/progress.md`, `docs/techdebt.md`) —
     docs-based модель;
   - `04-Memory/` — vault-модель: дописывай в `04-Memory/session-log/<дата>.md`
     по конвенции проекта.
   - Неоднозначность (несколько моделей или нет модели) — задай пользователю
     прямой вопрос, не выбирай молча. Если модели памяти нет — предложи
     создать `.opencode/memory/decisions.md`; без согласия ничего не создавай.
2. Прочитай ход сессии и дистиллируй:
   - решения: что выбрано и почему, какие альтернативы отклонены;
   - новые reusable patterns: что переносимо в другие сессии/проекты;
   - lessons: что не сработало, подводные камни;
   - confirmed facts vs proposals/open questions — разделяй явно:
     подтверждённое помечай как факт, непроверенное — как proposal/open
     question; не выдавай одно за другое;
   - следующий actionable focus: один конкретный следующий шаг.
3. Прочитай целевой файл памяти — не дублируй уже записанное (в том числе
   записанное через `/flush`). Пиши только новое.
4. Допиши новое в подходящий memory/docs файл. Формат — как существующие
   записи в нём. Кратно, на русском.
5. Если дистиллировать нечего (обсуждение не дало нового знания) — ответь
   «нечего dream» и ничего не пиши.

## Правила

- Append-only: не перезаписывай существующие записи журналов/реестров.
- Не пиши код/конфиги — только память/заметки. Это не зона dev-агентов.
- Не фиксируй secrets/credentials.
- Не коммить — коммит отдельной командой с явным approval.
- Команда исполняется только при явном запуске `/dream`; автоматической
  фоновой работы нет — не обещай её.
- Локальная команда проекта с тем же именем имеет приоритет над этой
  глобальной.

## Использование

- Запуск: `/dream` из любого проекта (global command:
  `~/.config/opencode/command/dream.md`).
- Изменение вступает в силу после перезапуска OpenCode: config и команды не
  hot-reload, активные сессии продолжают работать с уже загруженным конфигом.

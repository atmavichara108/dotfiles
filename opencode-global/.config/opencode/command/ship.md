# /ship — выкладка ветки одним заходом

Запуск команды пользователем = подтверждение всего заявленного scope.
Чужие ветки и чужая грязь — не scope: при их наличии остановиться и доложить.

## 0. Роутер: где мы?

Проверь корень репозитория:

- Есть `stow.sh` и каталог `opencode-global/` → это **dotfiles**, иди в раздел **A**.
- Иначе → **обычный репозиторий**, иди в раздел **B**.

## A. dotfiles-режим (полный цикл)

### A.0. Preflight — через копа, не глазами

**Обязательно первым шагом** (кредо: классификацию делает код, не модель):

```bash
python3 /home/rudra/dotfiles/opencode-global/.config/opencode/tools/tree-cop/tree-cop.py ship-check --mine <свой-путь> [--mine <...>]
```

Одна строка JSON: `verdict` GO/STOP, `mine`, `foreign`, `skip_worktree`,
`mode_changes`, `origin_main`, `reasons`.

- **GO** — продолжай, не перепроверяй руками то, что уже сказал коп.
- **STOP** — доложи вердикт и жди решения. Молча чинить запрещено.

Ручные `git status`/`fetch` после копа не нужны (коп сам делает fetch).

### A.1. Коммиты по зонам

- Один коммит = один сюжет/зона (гейт zone-mix). Несколько сюжетов — несколько коммитов.
- `MIXED_OK=1` только с причиной в сообщении (пример: гейт дублирует зоны по имени файла).
- Skip-worktree: свои правки в `agent/*.md` сначала `unskip`, после коммита вернуть бит.
- Mode: новым скриптам `update-index --chmod=+x` до коммита; mode-правки — только полным коммитом (pathspec сбрасывает mode в 644).
- Сообщения: `feat/fix/docs/test(chore): ...` + scope-пакет.

### A.2. Dream

- Дистиллировать сессию по правилам `/dream` в файл памяти проекта (append-only, без дублей).
- Память — тоже сюжет: отдельный `docs:`-коммит в той же ветке.
- Плюс строка-указатель в волт `04-Memory/session-log/<дата>.md`
  (`[ship:dotfiles]` + список коммитов) — след в хабе на случай потери проектной памяти.

### A.3. Merge + push + чистка

- `switch main` (дерево должно быть чистым — иначе стоп).
- Если своя грязь мешает переключению — убрать ТОЛЬКО её:
  `python3 /home/rudra/dotfiles/opencode-global/.config/opencode/tools/tree-cop/tree-cop.py stash-foreign --mine <...> -m "tree-cop: <причина>"`,
  и сразу после merge вернуть `... tree-cop.py pop`. Чужое не двигать.
- Merge ветки: FF если чистый, иначе `--no-ff` с сообщением `merge: <смысл> (<ветка>)`.
- `push origin main`. Только свои ветки; `--force` — никогда.
- Удалить task-ветку локально и на remote. Чужие ветки не трогать.
- Финал сессии — НОВАЯ ветка: `git switch -c task/next-<ГГГГММДД-ЧЧММ>` от
  обновлённого main. Сессия продолжается вне main (на main не работать);
  новую тему branch-auto и так уведёт в свою ветку.
- Финальный `status` + `log`: дерево чистое, `main == origin/main`.

### A.4. Отчёт

Что уехало (коммиты), что осталось открытым, что чужое замечено рядом.

## B. Обычный репозиторий (безопасный минимум)

Без tree-cop, зон и переключений веток. Только штатные операции:
`status`, `diff`, `log`, `add`, `commit`, `push`.

### B.0. Preflight глазами

- `git status --short --branch`, `git log --oneline -5`, `git diff --stat`.
- Чужое (не твои файлы, изменённые рядом) — не scope: доложи и жди решения, молча не чини.
- Дерево должно соответствовать текущей задаче, иначе стоп.

### B.1. Коммиты

- Сгруппируй изменения по смыслу, один коммит = один смысл.
- Сообщения conventional: `feat/fix/docs/test/chore: ...` (+ scope, если в репо так принято).
- Запрещено: `reset`, `checkout`, `clean`, `rebase`, `--force`, удаление чужих веток.

### B.2. Push

- `push` только своей текущей ветки. Merge в `main`/`master` автоматически НЕ делать — предложить отдельным шагом.
- Финальные `status` + `log`: дерево чистое относительно задачи.

### B.3. Память — обязательно (memory-gate)

Молчаливого «пропустить» нет. Порядок:

1. Определи модель памяти проекта (канон `/dream`):
   - `.opencode/memory/decisions.md` → пиши туда;
   - `docs/decisions.md` (+ `docs/progress.md`, `docs/techdebt.md` — по смыслу записи) → туда;
   - `04-Memory/session-log/<дата>.md` → туда, по конвенции проекта.
   - Несколько моделей или неясно — спроси пользователя, молча не выбирай.
2. Дистиллируй как `/dream`: решения, уроки, факты отдельно от гипотез,
   следующий фокус. Сначала прочитай целевой файл — пиши только новое
   (идемпотентность: повторный прогон не дублирует). Append-only, кратко,
   на русском, без секретов.
3. Нет никакой модели — запиши в волт: `04-Memory/session-log/<дата>.md`,
   секция с тегом проекта (`[ship:<проект>]`), тот же формат. Это запасной
   адрес, не свалка: только решения сессии, ничего лишнего.
4. Память — отдельный коммит в текущей ветке, не смешивать с кодом.

### B.4. Новая ветка (не оставаться в main/master)

- Финал — НОВАЯ ветка: `git switch -c task/<slug>` от текущего HEAD.
  Единственное разрешённое здесь переключение (создание новой своей ветки);
  чужие ветки не трогать, в `main`/`master` не работать.

### B.5. Отчёт

Что уехало (коммиты), что осталось открытым, что чужое замечено рядом.

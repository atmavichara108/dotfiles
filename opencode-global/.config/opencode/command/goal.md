# /goal — режим одной цели

Аргументы: `$ARGUMENTS`

## CLI-инвокатор (headless)

Для headless-вызовов (opencode run) slash-команда /goal недоступна.
Используй cmdline-инвокатор:
```
python3 ~/dotfiles/tools/goal/goal.py set "objective" [--criteria "c1" "c2"] [--kill "условие"]
python3 ~/dotfiles/tools/goal/goal.py show
python3 ~/dotfiles/tools/goal/goal.py done [--evidence "факт"]
python3 ~/dotfiles/tools/goal/goal.py drop [--reason "причина"]
python3 ~/dotfiles/tools/goal/goal.py pause | resume | clear
```
Хранилище общее: ~/.local/state/opencode/goal.json.

## Хранилище

Цель хранится в `~/.local/state/opencode/goal.json` (переживает ходы и компакт).
Формат:
```json
{
  "objective": "дословный текст владельца",
  "criteria": ["проверяемый критерий 1", "проверяемый критерий 2"],
  "kill": "условие останова",
  "wip": "один активный — нельзя иметь две цели одновременно",
  "status": "active|paused|done|dropped",
  "created_at": "ISO timestamp",
  "updated_at": "ISO timestamp",
  "evidence": []
}
```

## Команды

### `/goal <текст>` — поставить цель

1. Если уже есть активная цель — спроси: «Уже есть активная цель: <objective>. Заменить? (да/нет)». Без «да» — не менять.
2. Запроси у пользователя (если не указаны в аргументах):
   - **criteria** — проверяемые критерии (числа, файлы, тесты, HTTP-коды). Без критериев цель непроверяема.
   - **kill** — условие останова (что считать провалом).
3. Запиши в `~/.local/state/opencode/goal.json`:
   - `objective` = текст аргументов дословно (basis: quoted)
   - `criteria` = список критериев
   - `kill` = условие останова
   - `wip` = "один активный"
   - `status` = "active"
   - `created_at` = текущее время UTC
4. Выведи: «Цель поставлена: <objective>. Критерии: <список>. Останов: <kill>.»

### `/goal show` — показать текущую цель

Прочитай `~/.local/state/opencode/goal.json`. Если нет — «Активной цели нет.»
Иначе выведи objective, kill, status, и критерии с полем «проверено как?»:

```
Цель: <objective>
Останов: <kill>
Статус: <status>

Критерии:
  1. <критерий 1> — проверено: <evidence или «не проверено»>
  2. <критерий 2> — проверено: <evidence или «не проверено»>
  ...

Evidence: <список фактов>
```

Каждый критерий печатается с местом для отметки «проверено как?» —
чтобы проверка done была не в голове агента, а в выводе.

### `/goal done` — закрыть цель как достигнутую

1. Прочитай цель. Если нет активной — «Нет активной цели.»
2. Проверь каждый критерий: достигнут? (живой прогон, файл, тест, HTTP-код).
   Выведи таблицу: «критерий → проверено как? → результат (✓/✗)».
3. Если все критерии достигнуты:
   - `status` = "done", `updated_at` = текущее время
   - Запиши факт в `evidence`: «Цель достигнута: <objective>. Критерии: <список с результатами>.»
   - Выведи: «Цель достигнута. Evidence: <список>.»
4. **Автоповещение инициатору:** если цель была поставлена по запросу другой стороны (Лаба, ИЦ, ЦУ, ОШ, control-top и т.д.) — немедленно отправить письмо-рапорт через ship-mail с evidence (коммиты, что проверено). Не ждать, пока они спросят.
5. Если не все критерии достигнуты:
   - Выведи: «Критерии не выполнены: <список невыполненных>. Продолжать или /goal drop?»

### `/goal drop` — отменить цель

1. Прочитай цель. Если нет активной — «Нет активной цели.»
2. `status` = "dropped", `updated_at` = текущее время
3. Запиши в `evidence`: «Цель отменена: <objective>. Причина: <причина>.»
4. Выведи: «Цель отменена.»

### `/goal pause` / `/goal resume`

1. `status` = "paused" / "active", `updated_at` = текущее время
2. Выведи: «Цель приостановлена/возобновлена.»

## Правило каждого хода (автоматическое)

Если в `~/.local/state/opencode/goal.json` есть цель со `status: "active"`:
1. **Напоминание:** в начале хода агент обязан учитывать активную цель.
2. **Проверка:** каждый ход — проверить, достигнута ли цель по критериям.
3. Если цель достигнута — предложить `/goal done`.
4. Если kill-условие сработало — предложить `/goal drop`.

## Хранение (state-зона)

- Файл: `~/.local/state/opencode/goal.json`
- Переживает ходы и компакт (на диске, не в контексте).
- Один активный goal (wip: канон «один активный»).
- Append-only evidence (не перезаписывать прошлые записи).

## Гейты владельца

- Цель ставится только по явному указанию владельца (команда `/goal`).
- Без «да» конфиг не менять (гейт подтверждения).
- Секреты не хранить в goal.json.

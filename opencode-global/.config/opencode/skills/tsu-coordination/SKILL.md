# tsu-coordination — сверхнавык «Координация 3+ ведомств» (Р-003 навык 5)

## Когда включается
Задача затрагивает **три и более** ведомств, либо состоит из этапов, где выход одного — вход другого (структурные апгрейды, пленумы, сквозные линии — пример: «цифровой образ»: ИПТ-исследование → ХПФ-гейт → ИЦ-механизмы → Лаба-испытания → УАС-кафедра).

## Контур
1. **Декомпозиция по ведомствам**: карта «кто что делает» с границами (каждому — свой scope, чужое не трогать); стыки поимённо (что передаётся, в каком виде, кто принимает).
2. **Маршрут**: каждое ведомство — через /dispatch (адрес из peer-registry, провенанс, DoD); параллельные ветки — с явными точками сведения.
3. **Стыки**: для каждого — формат артефакта, условие приёмки, кто верифицирует; межведомственные согласования фиксируются письменно (письма, не «договорились на словах»).
4. **Сведение**: единый реестр линий (кто на каком шаге, evidence); /report-каденция владельцу без спама — по контрольным точкам.
5. **Вердикт**: общий — за ЦУ; спец-гейты (философский — ХПФ, приёмка кода — verifier) проходят до него; конфликт линий — эскалация владельцу одной строкой с вариантами.
6. **Память**: по завершении — артефакт (06-Audits) с провенансом, route-log append-only, строки реестров.

## Правила
- «Общение ≠ авторизация»: письмо соседу не создаёт задач — только подтверждённый scope исполняется.
- Владелец не бегает по палубам: система сама детектит рассинхрон (контрольные точки, evidence, route-log) и эскалирует одной строкой.
- Бюджет ноль; платное — никогда.

# tsu-ministry — сверхнавык «Модернизация и создание ведомств» (Р-003 навык 4)

Канон процедуры: [[02-Methods/ministry-calibration]] — 6 шагов × 3 варианта (A новое ведомство; B отдел при ведомстве; C портирование существующего).

## Шаги (единые)
1. **Repo-корень**: A — новый репо; B — отсек родителя; C — новый репо, перенос без потерь, старые следы помечены переехавшими (один источник).
2. **Конвенции**: письменный пакет (границы, гейты владельца, WIP, формат отчётов, память, стыки), подпись обеих сторон.
3. **Канал**: полный sessionID в peer-registry, liveness, письмо туда-обратно с delivery-check; **смоук из нового cwd обеими сторонами** (урок инцидента 2026-10-20: постановка в очередь и delivery-check проверяются из нового дома, queued/sent — в журнале).
4. **Память**: где живёт (репо docs/), append-only, basis: quoted, что в общий волт.
5. **Реестры**: оргструктура, карточка 03-Projects (repo:, spec-home:), стыки, peer-registry (каталог/агент).
6. **Смоук**: первый нейтральный мандат в новом доме + evidence по всем шести шагам.

## DoD
Все 6 шагов с evidence (путь+hash, письмо+delivery, строка реестра, подписи). Нет шага — не откалибровано, боевые мандаты запрещены.

## Антипаттерны
Калибровка по памяти без смоука; адрес из чата (INC-18); устные конвенции; дубли источника при переезде; боевые задачи до смоука; платные решения (бюджет владельца = ноль, только опенсорс/локально).

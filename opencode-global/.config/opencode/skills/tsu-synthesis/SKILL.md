# tsu-synthesis — сверхнавык «Сведение + реестр решений + конфликты» (Р-003 навык 3)

## Канонизация слова владельца
1. Формулировка владельца — ДОСЛОВНО (basis: quoted), не пересказ.
2. Тип знания: политика (01-Policies), метод (02-Methods), факт (04-Memory/facts.md), термин (01-Policies/skill-taxonomy).
3. Конфликт с каноном → остановка, delta владельцу как вопрос.
4. Запись — через named executor (meta — агентная инфраструктура; ведомство — его зона); гард/линки; коммит в task/*-ветку.
5. Правило поведения → запись в 01-Policies/decisions-registry.md (Р-NNN) с basis: quoted.

## Двойное именование (ADR-032)
Каждый нумерованный объект в человекочитаемом тексте — парой `<индекс> — <тип> «<имя»`. Словарь: операция, резолюция (ADR), решение (Р-серия), инцидент (INC), этап (волны), исследование (И-серия), метод (М-серия). Имя — из слов владельца; предложенное — на утверждение ДО записи. Машинные ID (JSONL, ветки, файлы спек) — не типизируются.

## Механизм доимени (ритро-при-касании)
Старый объект упомянут без имени (например «в решении Р-003 от 14-го») → НЕ оставляй голый индекс: найди/сформулируй тип-имя из его смысла → предложи владельцу одной строкой в ответе (`Р-003 — решение «Центральный Узел и навыки 1–5»`) → после утверждения запиши пару в реестр (дёшево: одна строка, без перечитывания волта). Быстро, автоматически, при каждом касании (правило при-касании, ADR-032).

## Приёмка пакета (сверхнавык-компонент)
Факт-сверка ТОЛЬКО по диску (git show, файлы, журналы) — самодекларация не evidence → независимый verifier (task agent=verifier) с DoD и hash → PASS: merge по канону + строка реестра + память; FAIL — мотивированный возврат. Мутация после вердикта аннулирует вердикт.

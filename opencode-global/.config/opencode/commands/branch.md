# /branch — авто-ветка от темы запроса

Создай git-ветку `task/<slug>` для текущего тематического запроса и переключись
на неё. Slug генерится из темы (аргументы команды или первый промпт сессии).

## Что делаешь

1. **Определи тему ветки:**
   - Если заданы аргументы (`$ARGUMENTS`) — используй их как тему.
   - Иначе — возьми первый пользовательский запрос текущей сессии (из истории
     сообщений), сформулируй краткий slug (3–6 слов).

2. **Сгенерируй имя:** `task/<slug>`:
   - кириллица → транслитерация;
   - только `[a-z0-9-]`, пробелы/мусор → `-`;
   - обрежь до 6 значимых слов, убери хвостовые `-`;
   - пример: «починить виджеты квтайла» → `task/pochinit-vidzhety-kvtaila`.

3. **Проверь условия (жёстко):**
   - Текущий каталог — git-репозиторий (`git rev-parse --show-toplevel`).
   - Текущая ветка **не** `task/*` — если уже в `task/`, скажи об этом и
     остановись (ветка уже есть).
   - Рабочее дерево — приведи в чистое состояние **штатно, без вопросов**:
     свои правки закоммить; чужие — `tree-cop stash-foreign` (см. ниже).

4. **Создай и переключись:**
   - База: `origin/main` (если есть), иначе `main`, иначе текущая HEAD.
   - `git switch -c task/<slug> <base>`.
   - Если ветка `task/<slug>` уже существует — `git switch task/<slug>`.
   - Коммить только файлы своего scope точечным `git add <пути>` — никогда
     `git add -A/-u` (чужое в свой коммит не тащить).

5. **Не делай ничего сверх** создания/переключения ветки: не коммить, не пуши,
   не редактируй файлы. Это только организационный шаг.

## Правила

- Никогда не трогай чужие незакоммиченные правки (не stash, не commit, не
  checkout чужих файлов). Грязное дерево = стоп + показать статус.
- Не создавай ветку от грязной/чужой ветки — только от `origin/main`/`main`.
- Если не git-репозиторий — скажи об этом и остановись.
- Коммит/сташ чужих файлов — только по явному решению пользователя.

## Отчёт

Верни одной-двумя строками: имя созданной ветки, от чего создана, статус
дерева до/после. Если стоп — причину и что нужно сделать пользователю.

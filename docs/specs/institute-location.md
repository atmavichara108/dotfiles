# Институт Передовых Технологий — локация-сессия сети

## Цель

Оформить Институт Передовых Технологий как явную локацию-сессию децентрализованной
сети исследований (по contract spec `ship-research-network.md`). Не создаёт
сессию-носитель, агентов и runtime. `kind: task`, `status: proposed`: документ
не разрешает runtime-внедрение сверх описанного; исполнение — после отдельного
одобрения scope Rudra.

## Существующая база (что закрепляется, а не строится)

- Contract spec §3, строка Института (правка 2026-10-13, слово Rudra): «Сам
  проводит исследования передовых технологий; принимает/находит внешний кейс,
  фиксирует provenance. Только когда признаёт находку годной — передаёт в
  Лабораторию (Ability Lab) на изолированную проверку.»
- Канон `00-WORLD.md` §VII (OpenCode-Vault): Институт (A6) — первый узел
  пайплайна «Институт → Лаборатория → доказанное».
- Recovered excerpt (contract spec, §2): «потерялся Институт Передовых
  Технологий — тоже определить релевантное место в инфраструктуре других
  институтов, лаб, учреждений как такую же отдельную сессию-локацию» (слово
  Rudra).
- Реестр исследований (OpenCode-Vault,
  `06-Audits/2026-10-13-ship-research-registry.md`): внешний вход сети.

## Что закрепляется (новое в этом документе)

1. **Имя локации:** «Институт Передовых Технологий» (Institute of Advanced
   Technologies).
2. **Компетенция** (слово Rudra 2026-10-13): сам проводит исследования
   передовых технологий — не почта и не маршрутизатор, исследовательский
   орган. Принимает/находит внешний кейс, фиксирует provenance (источник,
   контекст, дата).
3. **Граница передачи:** только когда Институт признаёт находку годной —
   передаёт её в Лабораторию (Ability Lab) на изолированную проверку.
4. **Место в пайплайне:** Институт (исследование) → Ability Lab (изолированная
   проверка; в Мир входит только доказанное — с обоснованиями, в т.ч. рисками
   и альтернативами) → решение Rudra → Инженерный Центр (внедрение).
5. **Приём и перенаправление интента:** интент в компетенции (исследование
   передовых технологий) — принимает; вне компетенции — перенаправляет
   релевантной локации через peer-comms с сохранением provenance (источник,
   исходный владелец, причина, статус), не дублируя владение; в один момент —
   один явный lead.
6. **Связь по peer-comms:** канал «на связи» (метод `peer-comms`,
   OpenCode-Vault). Общение ≠ авторизация.
7. **Карантин лора:** имена лора (Ekstasis / Alexander Maya / Allis Maya,
   Вельдора) не переносятся в инженерные решения; живут в лор-треке.

## Статус

Локация оформлена контрактом сети; операционная сессия-носитель не создана
(в отличие от Инженерного Центра, где ядро уже работает). Этот документ НЕ
создаёт сессию, агентов и runtime.

## Что этот документ НЕ делает

- Не создаёт сессию-локацию, агентов, runtime, интеграцию с внешними сервисами.
- Не запускает исследования (каждое — отдельный эксперимент со своим одобрением).
- Не решает, какие конкретно технологии исследовать (реестр исследований —
  рабочий документ сети).
- Не трогает frozen T-108/109/110. Не канонизирует лор.

## Порядок утверждения

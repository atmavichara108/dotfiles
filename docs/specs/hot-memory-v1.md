# hot-memory v1 — журнал, индекс, CLI

Решение владельца (2026-10-13, basis: quoted): «согласен, делаем» — форма
подтверждена: журнал (append-only, с принудительной записью на диск) + индекс
(ключ/путь/тег/время) + CLI; **RAM — только кеш, никогда единственное место**.
Дословные сообщения пользователя в горячий журнал по умолчанию **не** пишутся.

## 1. Зачем

2026-10-12 два неотправленных черновика пропали, потому что жили только в памяти
процесса. Горячая память закрывает класс потерь: всё, что обязано выжить
(черновики, состояние отсеков, принятые решения, «что сейчас в руках»), попадает
в явный журнал с индексом, а не в кучу рантайма.

Это также «око»: индекс даёт доступ по ключу/тегу/времени вместо чтения реестров
целиком.

## 2. Что НЕ делаем в v1

SQLite-бэкенд; семантический поиск; синхронизация между машинами; запись в
репозиторий; автосейв поля ввода TUI (это И-13, отдельно); автоматическая
загрузка чего-либо в контекст сессии; ретеншн старше месячной ротации.

Отдельно: **диалоги остаются в базе сессий** — второй правды рядом с ней не
создаём.

## 3. Границы

1. Данные — **вне репозитория**: `~/.local/state/opencode/hotmem/` (как журнал
   писем `mail/receipts-out.jsonl`). В git не попадает ничего.
2. **Секретов нет.** Запись, похожая на секрет (ключи, токены, `token=…`,
   приватные ключи), отклоняется с rc=3 и не попадает ни в журнал, ни в индекс.
3. Дословные сообщения пользователя — только по явному флагу `--verbatim`; их
   штатное место — память и handoffs.
4. Строка журнала ≤ **4 КБ** (PIPE_BUF): длинные тела — отказ с понятной ошибкой
   (позже: манифест + полезная нагрузка отдельным файлом).
5. RAM — только кеш. Если чего-то нет в журнале, для системы этого не существует.

## 4. Структура на диске

```
~/.local/state/opencode/hotmem/
  journal/<YYYY-MM>/<scope>.jsonl     # сегменты по месяцам, append-only
  index.jsonl                         # производный индекс (пересобираемый)
  doctor.log                          # результаты последней сверки
```

## 5. Схема записи (одна строка JSON на событие)

```json
{"ts": 1791850000000, "key": "draft:ses_ece7b76c8ffe", "scope": "host",
 "session": "ses_ece7b76c8ffe", "tags": ["draft", "tui"], "kind": "put",
 "len": 1234, "body": "…"}
```

- `key` — обязателен, стабильный адрес (не подпись): `draft:<session>`,
  `cell:<name>`, `decision:<id>`, `state:<tool>`.
- `kind`: `put` — запись в историю; `state` — последнее состояние по ключу
  (при чтении `state` приоритетнее `put`).
- `scope`: `host`, `repo:<name>`, `vault`.

## 6. CLI — `scripts/.local/bin/hotmem`

| Команда | Поведение |
|---|---|
| `hotmem put --key K [--tag T]… [--scope S] [--session S]` | тело из stdin (или `--body`), `kind=put` |
| `hotmem state --key K …` | то же, но `kind=state` (с fsync) |
| `hotmem get --key K [--json]` | последнее по ключу (`state` приоритетнее); `--json` — строка целиком |
| `hotmem list [--tag T] [--scope S] [--since TS] [--limit N]` | лента ключей |
| `hotmem grep PATTERN [--key K] [--tag T]` | поиск по телу |
| `hotmem doctor [--rebuild]` | сверка индекса с журналом; `--rebuild` пересобирает |
| `hotmem rotate` | закрыть текущий сегмент (месячная ротация) |

Коды возврата: `0` успех, `1` нет данных, `2` ошибка ввода, `3` отказано
(секрет/длина). Сообщения — на русском, кратко.

## 7. Политика записи

- **fsync** — на `state` и при закрытии верстака/фиксации решения; на `put` без
  fsync (потеря в пределах секунд допустима).
- Append без лока: строка < PIPE_BUF, одной записью.
- Индекс обновляется инкрементально; в конце сегмента хранится хэш последней
  учтённой строки — по нему `doctor` ловит дрейф.
- Ротация месячная, автоматическая при смене месяца.

## 8. Приёмка (verifier — по пунктам, с уликами)

1. `put`→`get` и `state`→`get` возвращают ровно то, что положили; `state`
   перекрывает предыдущее состояние того же ключа.
2. **Конкурентность:** два процесса пишут 10 000 строк одновременно — ни одной
   битой строки, все читаются.
3. `doctor` обнаруживает искусственно внесённый дрейф индекса и `--rebuild`
   восстанавливает согласованность.
4. **Секрет:** запись с токеном/ключом отклоняется (rc=3) и отсутствует в журнале
   и индексе.
5. **Длина:** тело > 4 КБ — отказ с понятной ошибкой, журнал не тронут.
6. **Замеры (И-14):** время `get` по ключу против чтения реестра целиком; `put`
   без fsync и с fsync (перцентили).
7. **Гигиена:** все файлы вне репозитория; `git status` в dotfiles чист.

## 9. Маршрут

`bash-dev` реализует в ветке `task/draft-loss-recovery-20261012` одним коммитом
(зона `scripts`) → `verifier` принимает по п.8 → `sysop` записывает результат в
память и обновляет инбокс (И-12/И-14).

## 10. Риски

| Риск | Митигация |
|---|---|
| Ключи без дисциплины → свалка | Правило: ключ — адрес, не подпись; список ключей в спеке-преемнике |
| Соблазн «второй правды» рядом с базой сессий | Прямой запрет в не-целях |
| Рост сегментов | Месячная ротация; ретеншн — отдельным решением |
| Потеря при `put` без fsync | Осознанно: `state` — с fsync, `put` — история |

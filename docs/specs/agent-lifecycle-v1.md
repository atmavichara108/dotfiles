# И-21 — жизненный цикл субагентов

## Источник (basis: quoted)

Слова Макса (2026-10-14), дословно:

> «субагент рождается - может эволюционировать, быть переиспользуем и сливаться
> с другими мелкими субагентами, проходить боевые честные проверки и есл не
> годен или не использовался - замораживать и разбирать на модули - окуратно,
> вдруг ещё пригодиться субагент. будт новое ведомство в будущем по агентскоми
> контуру.»

Домыслы отделены: ниже — рабочая операционализация этих слов, не его прямая
речь. Сама речь остаётся каноном.

## Состояния жизненного цикла

`born → active → evolving ⇄ reusable → battle-tested → {retired | frozen | merged}`

| Состояние | Значение | Переход |
|---|---|---|
| **born** | создан из архетипа (И-20), получил имя/зону/модель | после сборки из слотов |
| **active** | назначен на работу, владелец известен | первый dispatch |
| **evolving** | добирает схожие команды-модули, оптимизируется (И-22 классификатор) | накопление схожих модулей |
| **reusable** | переиспользуем между задачами, стабилен | подтверждённая повторная применимость |
| **battle-tested** | прошёл честные боевые проверки (verifier PASS на живом заказе) | реальный прогон, не синтаксис |
| **merged** | слит с другим мелким субагентом (слияние схожих) | решение при пересечении зон/модулей |
| **retired** | годен и использован — закрыт штатно | завершение сюжета |
| **frozen** | не годен ИЛИ не использовался — заморожен, НЕ удалён | простой / негодность |
| **decomposed** | разобран на модули — **осторожно**, на случай будущего применения | из frozen, точечно |

## Ключевые правила (из слов Макса)

1. **Рождение** — только из архетипа (слоты, белый список прав, модель).
2. **Эволюция** — добирает схожие команды-модули (правило 3/5 из И-22),
   оптимизируется при достижении условия. Классификатор — поставщик заказов.
3. **Переиспользование** — стабильный агент живёт между задачами, не
   пересоздаётся под каждый сюжет.
4. **Слияние** — мелкие схожие субагенты могут сливаться в одного.
5. **Боевые честные проверки** — только реальный прогон через verifier PASS,
   не «синтаксис OK» и не самоотчёт исполнителя.
6. **Списание мягкое:** не годен / не использовался → **заморозить** (frozen),
   не удалять. Разбор на модули — **осторожно**, «вдруг ещё пригодится
   субагент»: уникальное сохраняется, дубли и мёртвое уходит в модули.
7. **Ведомство агентского контура** — будущая структура (см. лексикон:
   «Инженерный Центр» + ведомство агентского контура). До её создания
   жизненным циклом владеет `sysop`.

## Реестр жизненного цикла (append-only)

Файл: `.opencode/memory/agent-lifecycle.jsonl` — по строке на агента:
`{name, born, owner, zone, model, state, last_used, notes}`. Смена состояния —
новая запись/дата, не перезапись (история — в git).

Существующие агенты при вводе реестра получают `born` = дата ввода, `state`
по факту (`active` для работающих, иначе `retired`/`frozen`).

# Инженерный Центр Корабля — локация-сессия сети

## Цель

Оформить Инженерный Центр Корабля как явную локацию-сессию децентрализованной
сети исследований (по contract spec `ship-research-network.md`), закрепив
существующее операционное ядро dotfiles. Не создаёт новых агентов, маршрутизатор,
телеметрию, skill tree runtime и не решает изоляцию ветки M Code (отдельный
эксперимент). `kind: task`, `status: proposed`: документ не разрешает runtime
внедрение сверх описанного; исполнение — после отдельного одобрения scope.

## Существующая база (что закрепляется, а не строится)

Инженерный Центр уже фактически работает как операционный слой dotfiles:

- primary `sysop` — оператор-оркестратор Manjaro;
- субагенты: planner (стратег), builder (строитель), verifier (acceptance),
  system-audit (read-only аудит), dev-роли (qtile/bash/util/stow);
- 10 пайплайнов-команд (`/sysaudit`, `/script`, `/qtile`, `/util`, `/prompt`,
  `/notify`, `/macro`, `/plugin`, `/loop`, `/flush`);
- память: `.opencode/memory/user-profile.md`, `decisions.md`, `docs/cheatsheets/`;
- ADR-реестр (`docs/decisions.md`).

## Что закрепляется (новое в этом документе)

1. **Имя локации:** «Инженерный Центр Корабля» (Engineering Center).
2. **Компетенция** (из contract spec, §3): надёжность Корабля, реестры, версии,
   целостность общей инфраструктуры, инвентаризация внутренних систем. **Не
   центр всех исследований** — только инженерная надёжность и реестры.
3. **Приём и перенаправление интента:** интент в компетенции — обрабатывает
   существующими командами/sysop; интент вне компетенции — перенаправляет
   релевантной локации через peer-comms с сохранением provenance (источник,
   исходный владелец, причина, статус), не дублируя владение; в один момент —
   один явный lead.
4. **Связь по peer-comms:** канал «на связи» (как у соседних локаций).
   Общение ≠ авторизация: письмо соседу не создаёт задач и не даёт прав;
   работает только явно подтверждённый Rudra scope. Механизм — метод
   `peer-comms` (OpenCode-Vault).
5. **Карантин лора:** имена лора (Ekstasis / Alexander Maya / Allis Maya,
   Вельдора) не переносятся в инженерные решения; они живут в §5–§6 contract
   spec и лор-треке.

## Что этот документ НЕ делает

- Не создаёт новых агентов, маршрутизатор, телеметрию, skill tree runtime.
- Не решает изоляцию записи M Code от общего checkout/ветки (открытый
  эксперимент, реестр исследований).
- Не трогает frozen T-108/109/110 (мост и permission experiments).
- Не канонизирует лор и не переносит его в инфраструктуру.

## Порядок утверждения

- **Кто утверждает:** Rudra (Макс) как капитан Корабля и финальный
  canon/approval gate.
- **Куда фиксируется:** карточка проекта dotfiles и/или route-log волта.
- **Что утверждает:** оформление Инженерного Центра как локации (имя,
  компетенция, правило перенаправления, связь по peer-comms). НЕ разблокирует
  создание новых агентов, runtime маршрутизатора, телеметрии или решение
  изоляции M Code — это отдельные задачи с собственным одобрением.

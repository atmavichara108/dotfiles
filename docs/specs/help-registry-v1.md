# help-registry v1 — единый реестр команд и подсказок

Заказ (дословно, сессия «Слой интерактивных подсказок и чит-щитов»):
«создать прослойку подсказок по использованию и управлению любым компонентом на
этой системе — от демонов до приложений… не будем создавать всё подряд, а будем
двигаться по потребностям и диалектически. начнём с аудита… например я забыл
комбинацию клавиш в ренджере или хочу что то сделать но не знаю на какие кнопки
нажать в нвиме... В дальнейшем эта сессия станет предтечей альфа слоя в пипбое».

Решение владельца (2026-10-13, basis: quoted): **«Рекомендация v1 (вариант A):
один реестр команд/подсказок + генераторы в rofi и navi; добавление новой
команды — через ту же rofi-форму; авто-назначение хоткея в v1 не делать,
свободные клавиши брать из уже существующего conflict-audit пипбоя. Канал в
пипбой — вторая фаза, когда реестр станет источником данных для „альфа-слоя“ — да».**

## 1. Что делаем

Один **реестр команд/подсказок** как единственный источник правды, и два
генератора представления из него:

1. **rofi-меню** — `helpctl rofi`: список команд с описанием и хоткеем, выбор
   запускает команду; отдельный пункт «добавить команду» открывает ту же форму.
2. **navi-шпаргалки** — `helpctl navi`: экспорт реестра в cheat-файлы navi
   (рядом с существующими `rudra/*.cheat`), чтобы `Ctrl+G` в zsh видел наши
   команды.

Плюс `helpctl keys` — **просмотр** хоткеев: парсит `qtile/.config/qtile/keys.py`
и показывает, какая клавиша привязана к совпадающей команде. Только чтение.

## 2. Что НЕ делаем в v1

Автоназначение хоткеев и авто-правка `keys.py`; канал в пипбой (фаза 2, когда
реестр станет источником для «альфа-слоя»); семантический поиск; синхронизация с
волтом; любой сетевой вызов.

## 3. Где живёт

Один **новый stow-пакет** `helpreg/` (данные и CLI вместе, один владелец, один
коммит):

```
helpreg/.config/help-registry/registry.jsonl   # реестр: одна запись = одна строка
helpreg/.local/bin/helpctl                      # CLI
```

Пакет добавляется одной строкой в `stow.sh` (отдельным коммитом — другая зона).

**Реестр — JSONL, не YAML.** Причина: добавление записи = `>>` одной строки,
никакой перезаписи файла и риска испортить форматирование.

## 4. Схема записи

```json
{"name": "qtile reload", "desc": "перезагрузить конфиг qtile",
 "cmd": "qtile cmd-obj -o cmd -f reload_config", "hint": "Super+Ctrl+R",
 "tags": ["qtile", "wm"], "source": "manual"}
```

- `name` — уникален (проверять при добавлении, дубликат отклонять);
- `desc` — человеческое описание (обязательно);
- `cmd` — что запускать (может быть пустым для чисто справочных записей);
- `hint` — подсказка по клавишам (произвольный текст; авто-назначения нет);
- `tags` — для фильтрации;
- `source` — `manual` | `qtile-keys` | `imported`.

**Секретов в реестре быть не может** — файл в репозитории. Запись, похожая на
секрет (ключ, токен), отклоняется при добавлении.

## 5. Контракт CLI

| Команда | Поведение |
|---|---|
| `helpctl list [--tag T] [--json]` | список записей (для конвейеров) |
| `helpctl rofi [--tag T]` | rofi-меню: выбор запускает `cmd`; отдельный пункт — добавить |
| `helpctl add` | форма (rofi) → валидация → дозапись строки в реестр; дубликат `name` — отказ |
| `helpctl navi [--out DIR]` | экспорт cheat-файлов в `~/.local/share/navi/cheats/rudra/` |
| `helpctl keys` | хоткеи из `qtile/.config/qtile/keys.py` рядом с записями (только чтение) |
| `helpctl check` | валидность реестра: JSON-строки, дубликаты `name`, отсутствие секретов |

Коды возврата: `0` успех, `1` пусто, `2` ошибка ввода, `3` отказ (дубликат/секрет).

## 6. Свободные клавиши

Источник — существующий конфликт-аудит хоткеев пипбоя
(`~/Projects/OpenCode-Vault/**/pipboy-hotkey-conflict-audit.md`) и
`docs/opencode-hotkeys-audit-2026-10-01.md`. В v1 они используются **только как
справка** при добавлении записи (показываются рядом), назначение — вручную.

## 7. Приёмка (verifier)

1. `helpctl list` показывает добавленные записи; `--json` даёт валидный JSON.
2. `helpctl add` дозаписывает ровно одну строку; `check` подтверждает валидность;
   повторное добавление того же `name` отклоняется (rc=3).
3. Секретоподобная запись отклоняется (rc=3) и в реестр не попадает.
4. `helpctl navi` создаёт/обновляет cheat-файлы; после этого `navi` показывает
   записи (проверить вызовом `navi --cheatsh`/по файлам).
5. `helpctl keys` читает `keys.py` и сопоставляет минимум одну реальную пару
   «команда — клавиша» (улика: вывод).
6. `helpctl rofi` открывается и запускает выбранную безопасную команду
   (проверка на безобидной команде, например `echo`); отдельный пункт добавления
   открывает форму.
7. Реестр и CLI лежат в репо, не содержат секретов; `stow -n helpreg` — чисто.

## 8. Маршрут и риски

`util-dev` реализует (коммиты: пакет `helpreg`; отдельно — строка в `stow.sh`)
→ `verifier` принимает по п.7 → `sysop` записывает результат в память.

Риски: соблазн автоматически править `keys.py` (запрещено в v1); разрастание
реестра без тегов (дисциплина: `tags` обязательны, если записей > 20); мёртвые
`cmd` (v1 не проверяет существование команды — отдельным решением позже).

# ADR-кандидат: гармоничное сосуществование движков «раз и навсегда»

> Ref: mcode-coexistence-20261016. Провенанс апрува: мандат Rudra (16.10) →
> ревью ЦУ APPROVE (17.10, ниты 1–4 в этой волне) → approval-гейт спеки
> исполнен решением ЦУ по зондам D1–D4. Слово Rudra: «опенкод — двигатель
> корабля; архитектура, позволяющая портировать неограниченно много SDK как
> дополнительных движков». Границы: правка движка mcode запрещена (И-33);
> ничего не удалять — только разделять зоны; миграции с сохранением содержимого.
> Стыковки: И-52 (worktree-видимость), И-53 Lineage (у mcode своя БД сессий —
> родословная движков вне этого ADR, см. §7).

## 1. Аудит: фактическая карта зон (2026-10-16, read-only)

### opencode-зона (наша, защищённый конец штанги)
| Путь | Nature |
|---|---|
| `~/.config/opencode/` | симлинки в `dotfiles/opencode-global/.config/opencode/` (агенты, команды, плагины, opencode.jsonc, providers.json) |
| `~/.local/share/opencode/opencode.db` | БД сессий движка (2.4GB) |
| `~/.local/state/opencode/` | почтовые квитанции, инциденты, shell-лог |
| `systemd/.config/systemd/user/opencode-serve.service` | user-unit `opencode serve` :49374 (мост T-156) |

### mcode-зона (чужая, не трогаем)
| Путь | Nature | Заметки |
|---|---|---|
| `~/.config/ai.mcode.desktop.dev/` | Electron-namespace десктопа (кэш, cookies, `mcode.settings`, логи, `opencode/locks`) | создан 2026-10-15 — это и есть «переименовал под себя»: новый namespaced каталог вместо старого |
| `~/.local/share/m-code-data/config/mcode.jsonc` | рабочий конфиг движка | SSOT-копия живёт у нас в dotfiles (см. §2) |
| `~/.local/share/m-code-data/config/opencode.jsonc` | **копия 2026-09-05**, маркер `.mcode-legacy-opencode-config-migration` («copied … files=opencode.jsonc») | то, что mcode «утащил»: разовая миграция, с 05.09 не обновляется — рассинхрон-ловушка |
| `~/.local/share/m-code-data/mcode/opencode.db*` | БД mcode с opencode-именами (форк-наследие) | трогать нельзя — живая БД |
| `~/.local/share/mcode/`, `~/.cache/mcode/` | orchestrator-json, кэш sidecar/bun | |

### наша же mcode-обвязка в dotfiles
- `mcode/` — пакет stow: `~/.local/bin/mcode-open` + `~/.local/share/applications/mcode.desktop` (симлинки живы с 05.09).
- **Дефект дрейфа: пакета `mcode` нет в `stow.sh`** → при полном перестове/новой машине обвязка молча не восстанавливается. Фикс — §5.D1.
- `opencode-global/.config/opencode/mcode.jsonc` — наш SSOT-исходник конфига mcode (спека provider-SSOT, done 01.10).
- **Симлинк `~/.config/mcode → dotfiles/opencode-global/.config/opencode` существует (с 10.07)** — т.е. `~/.config/mcode/mcode.jsonc` = наш SSOT-исходник. Потенциальный второй путь чтения конфига движком (если он уважает `$XDG_CONFIG_HOME/mcode/`); доказательств чтения из логов нет — основной подтверждённый источник: `m-code-data/config/mcode.jsonc`. Для движка безвреден в любом случае.

### диагноз «путаницы» (слова Rudra → механизмы)
1. **Namespace-миграция форка**: обновление переехало из старого desktop-каталога
   в `ai.mcode.desktop.dev` (идентификатор Electron). Наши конфиги не удалены —
   mcode скопировал `opencode.jsonc` к себе (05.09) и с тех пор живёт своей копией.
2. **Двойной SSOT провайдеров**: dotfiles-`opencode.jsonc` ≠ m-code-data-`mcode.jsonc` ≠ m-code-data-копия-`opencode.jsonc` (заморожена). Видимость расходилась уже (И-42/44 чинили).
3. **Имена-наследия**: внутри mcode-зоны файлы с именем `opencode*` (БД, конфиг-копия) — оптические ловушки при grep/чистках; это внутренность форка, переименовывать нельзя (правка движка запрещена), можно только маркировать.

## 2. Инварианты сосуществования («раз и навсегда»)

1. **Зонная изоляция.** Каждый движок владеет своим namespaced пространством;
   агентский контур (мы) пишет ТОЛЬКО в: свою opencode-зону, свой dotfiles-пакет
   любого движка, и SSOT-исходники. Зоны движков (`~/.config/ai.mcode.desktop.dev/`,
   `~/.local/share/m-code-data/`, `~/.local/share/mcode/`, `~/.cache/mcode/`) —
   read-only для нас. Взаимных переименований ни одна сторона не делает:
   форк-движки обновляются как есть.
2. **SSOT направление: dotfiles → движок, никогда наоборот.** Исходник конфига
   движка N лежит в `opencode-global/.config/opencode/<n>.jsonc`; доставка в
   зону движка — явная, идемпотентная, скриптом (`sync-<n>-config`), с диффом
   перед записью. Замороженные копии чужой миграции (m-code-data/opencode.jsonc)
   помечены как легаси, не правятся, не удаляются, в расчёт не идут.
3. **Общий слой — только контракты, не файлы.** Провайдеры — SSOT-спека done
   (провайдерные блоки синхронизируются точечно); оркестрация mcode→opencode —
   HTTP-мост T-156 (`opencode-serve.service`, 127.0.0.1:49374); обратный канал —
   git-дерево. Никаких общих записываемых файлов.
4. **Несовместимости фиксируются как границы, не чинятся молча.** ADR-019
   (mcode не исполняет глобальные плагины opencode), асимметрия API (32 vs 115
   путей), своя БД сессий mcode (Lineage-граница, §7).

## 3. Формула портируемости (канон Rudra, физический облик)

> **Новый SDK-движок = одна namespaced зона движка + один dotfiles-пакет +
> один SSOT-исходник + одна точка моста. Ноль правок в чужих зонах.**

Физически для движка `<n>` существуют:

| # | Артефакт | Путь | Кто создаёт |
|---|---|---|---|
| 1 | Зона движка | `~/.config/<namespace n>/`, `~/.local/share/<n>-data/…` (куда движок сам пишет) | сам движок, мы не трогаем |
| 2 | Dotfiles-пакет обвязки | `dotfiles/<n>/` (лаунчер, .desktop, свои user-юниты) — **в `stow.sh` обязательно** | мы |
| 3 | SSOT-исходник конфига | `dotfiles/opencode-global/.config/opencode/<n>.jsonc` | мы |
| 4 | Скрипт доставки | `scripts/.local/bin/sync-<n>-config.sh` (dotfiles→зона, diff-first, идемпотентен) | мы |
| 5 | Точка моста | реестр: движок слушает/обслуживает что, URL/юнит (T-156-паттерн `opencode-serve.service`) | мы, запись в реестр §4 |
| 6 | Запись в реестре движков | строка в `docs/engines.md`: имя, зона, SSOT-путь, скрипт, мост, известные границы (как ADR-019) | мы |

Расширение реестра — единственный «протокол» добавления движка: реестр имеет
владельца (ИЦ) и механизм отмирания (строка закрывается вместе с удалением
пакета) — анти-энтропийный инвариант ADR-028.

## 4. Реестр движков (живой артефакт формулы)

`docs/engines.md` — одна таблица, строки:

| Движок | Зона | SSOT | Доставка | Мост | Границы/примечания |
|---|---|---|---|---|---|
| opencode (ядро корабля) | `~/.config/opencode`→dotfiles; `~/.local/share/opencode` | `opencode.jsonc` | stow | `opencode-serve` :49374 | — |
| mcode (M Code Desktop) | `~/.config/ai.mcode.desktop.dev`; `~/.local/share/{mcode,m-code-data}` | `mcode.jsonc` | sync-mcode-config (D2) | клиент моста → :49374 | ADR-019; своя БД сессий; правка запрещена (И-33). ## 5. Fail-fast: зонды с kill-criterion

Метод: `06-Audits`-канон волта `02-Methods/fail-fast.md` (origin/main,
коммит 576d636 — персистентизирован по нашей заявке). Каждое решение — дешёвый
зонд, изоляция, явный критерий провала, opencode-конфиг не участвует в зонде
(защищённый конец штанги):

| # | Изменение | Зонд | Kill-criterion |
|---|---|---|---|
| D1 | `mcode` в `stow.sh` | `stow -n mcode` (dry-run, 0 записи) | конфликт симлинков → не мержим, чиним пакет |
| D2 | `sync-mcode-config.sh` (dotfiles→`m-code-data/config/mcode.jsonc`) | `--dry-run` печатает diff; живой прогон только при diff≠∅ | (а) diff трогает ключи/секреты → стоп; (б) mcode после синка не стартует → откат копией `.bak` (скрипт делает бэкап перед записью); (в) **движок читает НЕ тот файл** — подтверждающий зонд источника чтения после обновления 15.10 (разовый logs/strace: какой конфиг реально открывается); наш «подтверждённый источник» датирован до обновления |
| D3 | Маркировка легаси-копии | запись только в наш реестр (чужой файл не правим) | — (неинвазивно) |
| D4 | Реестр `docs/engines.md` | нет рантайм-эффекта | — |
| Зонд-антипаттерн (НЕ делаем) | эксперименты прямо в живой `m-code-data/config/` | — | убит на уровне гипотезы: нарушает инвариант §2.2 |

**Канонические семь критериев (рубрика 02-Methods/fail-fast.md) — на схему в целом:**
эффективность — да (убирает ручной рассинхрон провайдеров, цена ошибки = зонд);
применимость — работает в текущем потоке (оба движка живы, stow-контур штатный);
эволюция — формула 6 артефактов масштабируется на N движков без переделки;
жизнестойкость — откат через .bak/stow -D, деградация в «как было»;
воспроизводимость — спека + dry-run повторяемы любой сессией;
универсальность — формула движко-независима (mcode как экземпляр);
антихрупкость — каждый провал зонда → запись в реестр границ (§4), схема
становится точнее от сбоев.

**Производные проверки зонда** (наши, дополнительные к канону): обратимость
(dry-run/бэкапы), неизвазивность к opencode-зоне, отсутствие необратимых
операций, стоимость провала = секунды, видимость результата (diff/стата stow),
владелец артефакта (ИЦ), механизм отмирания (строка реестра ↔ пакет).

## 6. Scope исполнения (после approval, отдельным коммитом)

In: D1 (`mcode` в stow.sh), D2 (скрипт sync-mcode-config), D3-D4 (реестр).
Out: любые правки в `~/.local/share/m-code-data/`, `ai.mcode.desktop.dev/`,
движке; перенос БД; Lineage-обвязка mcode (И-53, позже); secrets.

## 7. Границы и открытое

- **И-53 Lineage**: у mcode своя БД сессий — родословная «сессия×ветка» для
  второго движка = отдельный слой ledger'а (ключ движок+session_id). Отмечено
  как граница: текущий ADR не вводит кросс-движковых ключей.
- **И-52**: worktree mcode-проектов уже видны в волт-репо git-деревом — мост
  не нужен.
- **Метод fail-fast**: персистентизирован волтом по нашей заявке —
  02-Methods/fail-fast.md, origin/main, коммит 576d636 (закрыто 17.10).
- **`~/.config/mcode` симлинк** (10.07 → opencode-global) — решение ревью ЦУ
  17.10: НЕ удалять (защищённый конец), в реестре помечен неактивным каналом;
  удаление — только по evidence зонда (движок читает И расходится с SSOT).

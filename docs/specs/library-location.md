# Библиотека (NotebookLM) — локация-сессия сети

## Цель

Оформить Библиотеку как явную локацию-сессию децентрализованной сети
исследований (по contract spec `ship-research-network.md`). Не создаёт
интеграцию с NotebookLM, сессию-носитель, агентов и runtime. `kind: task`,
`status: proposed`: исполнение — после отдельного одобрения scope Rudra.

## Существующая база (что закрепляется, а не строится)

- Пересказ слова Rudra 2026-10-13 (недословно; источники: реестр OpenCode-Vault 06-Audits/2026-10-13-ship-research-registry.md — «интеграция памяти, предположительно второй brain на NotebookLM (Google)», и session-log волта 2026-10-13): Библиотека — локация с интеграцией памяти, предположительно второй brain на NotebookLM (Google). Кандидат-локация.
- NotebookLM — внешний сервис Google (notebooklm.google.com); «второй brain» —
  роль инструмента, не лор.
- Память экосистемы: `04-Memory/` волта — SSOT памяти; Библиотека — слой
  структурированного хранения/извлечения, не дубль SSOT.

## Что закрепляется (новое в этом документе)

1. **Имя локации:** «Библиотека» (Library); основной инструмент — NotebookLM
   (Google).
2. **Компетенция:** структурированное хранение и извлечение знаний Корабля;
   «второй brain» — слой памяти поверх рабочих контекстов; интеграция памяти
   (связь знаний между проектами и локациями).
3. **Границы:** Библиотека хранит и находит; не исследует (Институт /
   Ability Lab), не внедряет (Инженерный Центр), не канонизирует (Rudra).
4. **Статус:** кандидат, не runtime. Интеграция с NotebookLM этим документом
   не создаётся; сессия-носитель не создана.
5. **Приём и перенаправление интента:** интент в компетенции (хранение /
   извлечение знаний, структура памяти) — принимает; вне компетенции —
   перенаправляет релевантной локации через peer-comms с сохранением
   provenance (источник, исходный владелец, причина, статус), не дублируя
   владение; в один момент — один явный lead.
6. **Связь по peer-comms:** канал «на связи» (метод `peer-comms`,
   OpenCode-Vault). Общение ≠ авторизация.
7. **Карантин лора:** имена лора (включая Obsidian-хранителя) не переносятся
   в инженерные решения; живут в лор-треке.

## Что этот документ НЕ делает

- Не создаёт интеграцию с NotebookLM (аккаунт, ноутбуки, доступ — отдельные
  задачи с собственным одобрением).
- Не создаёт сессию-локацию, агентов, runtime.
- Не переносит существующую память (`04-Memory` волта остаётся SSOT; любое
  решение о зеркалах — отдельное).
- Не трогает frozen T-108/109/110. Не канонизирует лор.

## Порядок утверждения

- **Кто утверждает:** Rudra (Макс) как капитан Корабля и финальный
  canon/approval gate.
- **Куда фиксируется:** карточка проекта dotfiles и/или route-log волта.
- **Что утверждает:** оформление Библиотеки как локации (имя, компетенция,
  статус кандидата). НЕ разблокирует интеграцию NotebookLM, создание
  сессии/агентов — это отдельные задачи с собственным одобрением.

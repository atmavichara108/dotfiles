# Следопыт — трекер постановок (read-only агрегат)

- Мандат: ЦУ (ref follower-tool-design, 2026-11-01), слово владельца
  (basis: quoted): «придумай себе какой нибудь удобный инструмент и попроси
  иц спроектировать его тебе и сделать, хоть свой софт, хоть что то из
  опенсорса или что то гибрид».
- Кто: заказчик — ЦУ (несёт много линий: ведомства, квесты, мандаты,
  ожидания); проектирование и реализация — ИЦ.

## Цель

Один экран «где всё и на какой стадии»: агрегат **только чтение** из
существующих файлов, четыре состояния, алерт стагнации, выход — одна
страница текста + машиночитаемая строка.

## Scope v0.1

**Источники (только чтение, запись в чужие реестры запрещена — Р-056):**

| Источник | Путь |
|---|---|
| Реестр квестов | `~/Projects/OpenCode-Vault/11-Quests/quests.md` |
| Трекер задач | `~/Projects/OpenCode-Vault/TASKS.md` |
| Ожидания ship-mail | `~/.local/share/ship-mail/waits.jsonl` |
| Журнал сессий | `~/Projects/OpenCode-Vault/04-Memory/session-log/*.md` |
| Реестр решений | `~/Projects/OpenCode-Vault/docs/org/decision-registry.md` |
| Цели (агрегат+сайдкары+общие) | `~/.local/state/opencode/goal.json`, `goals/*.json` |

**Четыре состояния (канон ЦУ):**

1. `зафиксировано` — записано, не начато (ready/backlog/planned/locked*);
2. `в работе` — активно (active/in_progress/working);
3. `ждёт слова` — ожидание чужого действия/слова (wait с TTL, blocked,
   paused, overdue*);
4. `закрыто` — завершено с evidence (done/dropped + где есть ссылка на факт).

Звёздочка: `locked` с явным условием ожидания (словом владельца, преусловием)
= `ждёт слова`; без условия — `зафиксировано`. Каждая распарсенная строка
обязана получить ровно одно из четырёх состояний.

**Алерт стагнации (пороги настраиваемы, `~/.local/state/opencode/follower.json`):**

- `wait_hours` (default 48) — ожидание старше порога;
- `idle_days` (default 7) — строка в `в работе`, но не упоминалась в
  session-log за N дней (last-seen по ID/заголовку);
- просроченное ожидание (TTL исчерпан) — алерт сразу, порог не нужен;
- строка без состояния = **дефект агрегатора**, печатается в секцию
  `UNSTATED` и возвращает rc=2.

**Выход:**

- человек: секции по состояниям + секция `СИГНАЛЫ` (стагнация, полпути,
  просрочки) — один экран;
- машиночитаемая строка: одна JSON-строка `{ts, total, stated, unstated,
  by_state, alerts:[{id, reason}], sources:[{path, rows, ok}]}` в stdout
  после `--json-line` (или в файл `logs/follower/follower.jsonl`).

## Вердикт по open-source (исследование 2026-11-01)

Кандидаты: `bea` (bea-rs), `frame`, `taskmd`, `tl` (taskledger), `north`,
`tli`, `workctl`. Общий признак: **все — свои реестры задач** (свой формат,
`init`, перенос задач внутрь). Требование заказчика №1 («один источник —
файлы, что уже есть, НЕ новый ручной реестр») они нарушают по построению:
чтобы ими пользоваться, надо вести второй реестр параллельно первым пяти.

**Вердикт: свой софт** — тонкий read-only агрегатор (~строки на парсер +
агрегация), без своей базы, без daemon, без записи. Гибрид отпадает: чужой
CLI здесь не добавляет чтения наших форматов, он добавляет свою базу. Если
позади источники вырастут до единого schema — пересмотреть.

## Критерии приёмки (задал заказчик)

1. Прогон на текущем состоянии Корабля (десятки линий) — не на заглушке.
2. «Ни одной строки без состояния»: секция UNSTATED пуста, rc≠2.
3. Read-only: за прогоном mtime всех источников не меняется.
4. Сигналы честные: алерт = факт из файла (TTL, дата, отсутствие упоминания),
   не домысел.

## Вне scope v0.1

Запись чего-либо в источники; свой реестр/база; интерактивный TUI;
рассылка алертов (выход готов к рассылке строкой — отправка отдельным шагом).

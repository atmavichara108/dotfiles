# L9 — корневая причина FAIL релевантности (итерация 1)

Артефакт испытания. Скрипты диагностики: `tools/lab-l9/diag_*.py` (тот же venv).

## Симптом

Один и тот же top-1 (`04-Memory/session-log/2026-07-12.md#L1`) на всех 10
запросах набора A; A1–A7 нерелевантны; негативы polluted (top≈0.84 до
центрирования).

## Цепочка гипотез и проверки

1. **H1 префиксы e5 (`query:`/`passage:`)** — опровергнута: build и query
   всегда использовали корректные префиксы.
2. **H2 чанки-магниты** — частична: 7 чанков <200 симв.; добавлена склейка
   `MIN_CHUNK=200`. Не изменило top-1.
3. **Анизотропия mean-pool** — подтверждена частично: центрирование против
   центроида корпуса развело скоры (0.84→0.62), ранжирование не исправило.
4. **Токенизация кириллицы (гипотеза ЦУ)** — ПОДТВЕРЖДЕНА как корень
   (diag6c, см. п.6): куски RU-слов маппятся на чужие записи vocab.
5. **Смысловое пространство эмбеддингов** — ВЫРОЖДЕНО (diag7, прогон
   2026-10-15, базовая фраза «Собака гуляет в парке»):
   - синоним ru («Пёс гуляет по парку») = 0.9635;
   - перевод en↔ru той же фразы = 0.9129 — НИЖЕ, чем нерелевантная пара;
   - нерелевантная тема («Кот спит на подоконнике») = 0.9640;
   - чужая тема той же длины («Квантовая хромодинамика…») = 0.9698;
   - идентичная фраза +1 слово = 0.9963; +10 слов = 0.9758;
   косинус кодирует длину и лексическое перекрытие, семантика не читается.
6. **Токенизация — ФИНАЛЬНОЕ ДОКАЗАТЕЛЬСТВО (diag6c, прогон 2026-10-15):**
   кириллические слова попадают в ИСКРивлённые слои vocab:
   - «Собака гуляет в парке» → 4 куска, три из них ` for` (кусок
     английского «for»), один ` в`;
   - «Кот спит на подоконнике» → ` кот`, ` for`, ` на`, ` for` — глаголы
     («гуляет», «спит») схлопнуты в один id ` for`;
   - round-trip детокенизации RU неточен; EN-фраза токенизируется корректно
     (` a`, ` dog`, ` in`, ` the`, ` park`).
   - механизм BertTokenizerGGUF цел, но **кириллическая секция vocab в этом
     GGUF-конверте рассинхронизирована с id** — русские слова читаются
     моделью как мусор/чужие куски. Это и есть корень: эмбеддинги русских
     текстов не несут смысла; «транслит≈кириллица» (0.9884) и «любой RU-запрос
     близок к любому RU-чанку» — следствия.

## Корень

Артефакт `multilingual-e5-small-Q8_0.gguf` (repo `keisuke-miyako/…`,
`general.organization = "Tmp"`, `general.architecture = bert` — неофициальный
bert-GGUF, не основной путь llama.cpp). В этом конверте отображение
токен-id ↔ кусок vocab для кириллицы рассинхронизировано (diag6c): реальные
русские wordpiece-куски подменяются чужими записями (` for`), детокенизация
RU неточна. Английская часть vocab цела — отсюда корректный EN и полное
вырождение RU. Механизмы llama.cpp (tokenizer-BERT, mean-pool
`bert.pooling_type=1`) исправны; дефект — в данных/конвертации артефакта.

- Инструмент `tools/lab-l9/` (corpus/lab9/runset/baseline) — без изменений,

  остаётся корректной мерой для mean-pool pooling).

## Кандидаты итерации 2 (отдельный scope по слову Rudra)

1. Валидный билд multilingual-e5-small (f16-GGUF из ggml-org/канонической
   конвертации, либо HF-путь через `sentence-transformers` — но это новые
   зависимости вне текущего venv).
2. Модель B: Qwen3-Embedding-0.6B — качество выше, ожидаемый риск по таймингу
   (критерий 50 мс под вопросом на CPU).

## Вердикт итерации 1

**FAIL по критерию релевантности; PASS по таймингу** (median 13.1 мс,
p95 24.6 мс, 35 замеров; cold start 545 мс отдельно). Причина — непригодный
GGUF-артефакт модели A, не протокол и не механика индекса.

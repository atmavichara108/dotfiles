# Спека: pin-guard — проверка пинов моделей агентов против живого каталога

Статус: черновик на приёмку ЦУ · Автор: Мастерская Багфикс (mechanic) · Дата: 2026-11-19
Инцидент: BF-20261119-05 · Ветка: `task/fix-pin-guard-20261119`

## 1. Проблема

Пин модели, которой нет в каталоге OpenCode, **не даёт ошибки**: сервер принимает
`POST /api/session/<id>/model` с кодом `204`, модель сохраняется в сессии как
заказанная, а на запросе сессия тихо уходит на дефолтную модель агента.

Экземпляры:

1. **19.11 (подтверждён ИЦ):** verifier был запинен на
   `nvidia/moonshotai/kimi-k2.6` — такой модели в каталоге нет; вызов ушёл на
   дефолт агента — AMD-ключ с лимитом 1 запрос/сутки. ИЦ починил пин
   (`53b8b37`), но **механизма, который бы поймал это до коммита, не было**.
2. **19.11 (найдено при разборе):** `.opencode/agent/sysop.md` (primary dotfiles)
   запинен на `opencode/muse-spark-1.3-contributor-free` — такого id в живом
   каталоге нет (в снапшоте models.dev от 16.11 он ещё был → каталог Zen
   изменился). Тот же пин продублирован в `AGENTS.md`,
   `.opencode/memory/agent-lifecycle.jsonl`, `tools/orch-guard/orch-guard.py`.
   Сам пин не меняется: модельное изменение — по слову владельца (решение
   Ротации моделей).

Следствие: «битый пин» выглядит как «работает», а на деле тратит чужую квоту
и подменяет модель проверяющего.

## 2. Цель

Сделать битый пин **громким**: до того, как он попадёт в репозиторий и станет
невидимым, — остановить коммит; в уже существующем состоянии — показывать
каждый прогон.

## 3. Границы

**В объёме (dotfiles-инфраструктура):**

- `tools/model-watch/pin-check.py` — проверка пинов против каталога;
- `tools/model-watch/pin-check-selftest.py` — сухой прогон инструмента;
- `githooks/pre-commit` — гейт 9 (блокирующий);
- `tools/model-watch/README.md` — раздел про инструмент.

**Вне объёма:**

- правка самих пинов (модельное изменение — по слову владельца, зона Ротации);
- починка ядра OpenCode (валидация модели при установке) — чужой харнес:
  обход + запись-факт;
- `tools/orch-guard` и `AGENTS.md` не трогаем: правка пина — отдельное решение.

## 4. Контракт инструмента

### 4.1 Источник каталога

- **Единственный авторитетный источник — `GET {OPENCODE_ENDPOINT}/api/model`**
  живой машины (канон метода «Проверка живости модели»). Токен —
  `~/.config/opencode/service.json` (тот же путь, что у `wake.py`).
- `GET /api/provider` **не используется**: у openai-compatible провайдеров
  (`nvidia` и др.) он возвращает пустой список, что не значит «моделей нет».
- `--offline` (снапшот `control-plane/model-catalog.json` из models.dev) —
  **advisory**: каталог models.dev ≠ каталог провайдера у OpenCode (пример:
  `vercel/recursive/flint-v1.0` в models.dev отсутствует, в живом каталоге есть).
  В offline-режиме отсутствие пина печатается как предупреждение и **не**
  блокирует коммит.

### 4.2 Источники пинов

- `--agents-dir DIR` — каталог агентских `.md` (по умолчанию оба слоя dotfiles:
  `.opencode/agent` и `opencode-global/.config/opencode/agent`);
- `--staged` — пины из индекса git: проверяется то, что **попадёт в коммит**
  (починенный пин проходит гейт тем же коммитом);
- `--live-layer` — дополнительно живой слой `~/.config/opencode/agent`.

Пин читается из frontmatter (`model:`). Не считаются пинами: агент без `model:`,
шаблон с плейсхолдером (`{{МОДЕЛЬ}}`), неразбираемый формат без `/`.

### 4.3 Diff-гейт (главное правило)

В режиме `--staged` блокируется только **новый** битый пин — тот, который не был
битым в `HEAD` (базовая линия). Уже сломанный пин (решение по нему ещё не
принято) печатается как ⚠️ и **не блокирует** чужие коммиты: иначе один старый
пин (`sysop`) встал бы весь флот. `--strict` отключает правило (ручная проверка
флота: любой битый пин = FAIL).

### 4.4 Коды возврата и обход

| Код | Значение |
|-----|----------|
| 0 | все пины в каталоге; либо живой каталог недоступен (тогда — явный WARN, проверка пропущена); либо только ранее битые пины в `--staged` |
| 1 | найден новый битый пин (в `--staged`) либо любой битый пин (без `--staged` / с `--strict`) |
| 2 | ошибка запуска (usage) |

- Живой каталог недоступен → **не блокировать** флот: печатается WARN, код 0.
  Молчаливый PASS без предупреждения — тот же дефект, который чиним.
- Осознанный обход: `PIN_OK=1` (причина обязательна в сообщении коммита) —
- как `MIXED_OK=1`, `CLAIM_OK=1`, `SECRET_SCAN_OK=1` в том же хуке.

### 4.5 Гейт в `githooks/pre-commit`

- Срабатывает, только если в staged есть файлы `*/agent/*.md`.
- Запускает `python3 tools/model-watch/pin-check.py --staged --quiet --repo <repo>`.
- Ненулевой код → коммит остановлен с объяснением (имя агента, пин, причина).
- Обход гейта: `PIN_OK=1`.

### 4.6 Отчёт

`~/.local/state/opencode/model-watch/pin-report.json` — только метаданные:
время, источник каталога, статус, число пинов, список находок (агент, пин,
причина). Без секретов и без тел промптов.

## 5. Критерии приёмки (verifier, другая модель)

1. `python3 tools/model-watch/pin-check-selftest.py` — все проверки зелёные,
   ожидаемое число проверок зафиксировано в выводе.
2. На живом окружении: `python3 tools/model-watch/pin-check.py` находит пин
   `sysop` (`opencode/muse-spark-1.3-contributor-free`) как битый → код 1.
3. `--staged` на фикстуре: новый битый пин → код 1; только ранее битый пин →
   код 0 с ⚠️; `--strict` → код 1.
4. `bash -n githooks/pre-commit` — синтаксис цел; гейт 9 присутствует и
   срабатывает на staged-изменении агентского `.md` с новым битым пином.
5. `PIN_OK=1` → код 0, обход работает.
6. При недоступном сервере (недоступный `OPENCODE_ENDPOINT`) → код 0 + WARN.
7. Секретов и абсолютных путей с токенами в отчёте нет.

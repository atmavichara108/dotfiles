# Реестр ожиданий: отчёт «ответ без пришивки» (`waits.py stitch-report`)

- Канон: Р-092 (пришивка ответа), Р-075 (TTL — каденс пинка), Р-090 (формат
  письма/линт), Р-105 (важное — на диск).
- Основание: инцидент BF-20261119-02 (19.11, dotfiles) — отбор в отчёте был
  инвертирован: показывались строки, пришитые штатно, а закрытые без пришивки
  не показывались вовсе.
- Инструмент: `tools/ship-mail/waits.py` (`cmd_stitch_report`), потребители:
  `ship-mail.sh inbox|show` (грепают маркер «ОТВЕТ БЕЗ ПРИШИВКИ»),
  `tools/ship-mail/waits-stitch-report-selftest.py`.

## Термины

| Термин | Значение |
|---|---|
| закрытие | строка ожидания снята через `waits.py done` (в журнале закрытий запись с `op` = пусто) |
| пришивка | связь ответа с ожиданием: `op=stitch` (штатно) или `op=stitch-recovery` (восстановление) |
| пометка | запись `op=close-note` и прочие side-записи — НЕ закрытие ожидания |
| ответ | письмо от `who_owes` в ящике `who_waits`, отправленное не раньше `since` (детектор `_detect_reply`) |

## Нормативные правила отчёта

1. **Отчёт показывает закрытия без пришивки.** Строка попадает в отчёт, если
   она закрыта (в журнале закрытий её запись без `op`) и ни одна запись
   этого же `id` не имеет `op=stitch`/`op=stitch-recovery`.
2. **Пометки не закрытия.** Записи с `op=close-note` и любым иным `op`,
   кроме `stitch`/`stitch-recovery`, в отчёт не идут.
3. **Одна строка отчёта на `id`.** Журнал append-only: на один `id` бывает
   несколько записей — дедуп обязателен.
4. **Честная пометка о наличии ответа.** Для каждой строки определяется ответ
   по `_detect_reply`; в строке отчёта — «ответ найден» либо «ответ не найден».
   Отсутствие письма-ответа не отменяет саму строку отчёта: закрытие без
   пришивки — уже потеря связи.
5. **Окно жизни 24ч** (`op_deadline_minutes`, по умолчанию 24×60 мин). Строки
   старше окна не идут в подробности, а считаются сводкой
   «СТАРЫЕ БЕЗ ПРИШИВКИ» — старый шум не возвращается, но и не прячется.
6. **Строка отчёта несёт готовый путь починки:**
   `waits.py stitch <id> --recover --evidence "<чем доказан ответ>"
   --authorized-by "<кто санкционировал>" --answered-at <ISO ответа>`.
   Восстановление — штатный путь (`stitch --recover`), а не запись руками в
   журнал.
7. **Момент закрытия не теряет связь.** `waits.py done` при уже пришедшем
   ответе печатает ВНИМАНИЕ с той же командой починки.

## Инварианты

- Отчёт **read-only**: не меняет журналы, не пишет письма, не меняет состояния
  строк (только `stitch --recover` и `done` меняют).
- Журнал закрытий остаётся append-only: `stitch --recover` дописывает запись,
  прежние не переписываются.
- Ошибка в детекте ответа не ломает отчёт: неразобранное значение → «ответ не
  найден», а не падение.

## Вне области

`waits.py sweep` (авто-пришивка по найденному ответу), `waits.py autoping`
(пинги просроченных строк), `ship-mail.sh send` (доставка писем) — зоны
своих спецификаций; этот документ описывает только отчёт.

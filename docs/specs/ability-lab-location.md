# Ability Lab / Лаборатория — локация-сессия сети

## Цель

Оформить Ability Lab / Лабораторию как явную локацию-сессию децентрализованной
сети исследований (по contract spec `ship-research-network.md`), закрепив
существующее: очередь испытаний L1–L6, канонический пайплайн
«Институт → Лаборатория → доказанное» и описание органа. Не создаёт runtime,
агентов, банка данных и не запускает испытания. `kind: task`, `status:
proposed`: документ не разрешает runtime-внедрение сверх описанного;
исполнение — после отдельного одобрения scope Rudra.

## Существующая база (что закрепляется, а не строится)

- Очередь испытаний L1–L6 с критериями passing — `06-Audits/2026-10-07-lab-queue.md`
  (OpenCode-Vault): L1 шлюз М Code ↔ opencode; L2 ТАРДИС-структура; L3
  JARVIS-контур; L4 HEV-хранитель; L5 COMP-гибрид (принято внедрять); L6
  Дроны Культуры. Источник — слово Rudra 2026-10-07 (stream-intent-041/043).
  (Граница: §VII упоминает также L7 «Слуга Мира» — вне этого документа; очередь ограничена L1–L6 по lab-queue.)
- Канон пайплайна — `00-WORLD.md` §VII (OpenCode-Vault): Институт передовых
  технологий принимает внешние находки → Лаборатория испытывает изолированно → в Мир
  входит только доказанное.
- Описание органа Ability Lab — idea-graph (`organ-ability-lab`) и
  `06-Audits/2026-10-06-game-mechanics-map-draft.md`: изолированная проверка
  новых способностей. EEG/айтрекинг — названная область (contract spec §3).
- Мост peer-comms с сессией «Инженерный центр и параллельные лаборатории
  Корабля» (sysop/dotfiles): рукопожатие 2026-10-13, канал работает.
  Существование отдельных лабораторных сессий этим документом не утверждается.
- Живая проверка правила перенаправления (§4) пройдена 2026-10-13: sysop
  (Инженерный Центр) перенаправил тестовый интент L2 в Ability Lab /
  Лабораторию с provenance, без исполнения.

## Что закрепляется (новое в этом документе)

1. **Имя локации:** «Ability Lab / Лаборатория».
2. **Компетенция** (из contract spec, §3): изолированная проверка новых
   способностей Корабля; applied experiments (EEG/айтрекинг — названная
   область). Один эксперимент = гипотеза + протокол + критерий «годится».
3. **Статус:** кандидат, не runtime. Очередь L1–L6 размечена, критерии passing
   есть; runtime-исполнение очереди этим документом не создаётся.
4. **Пайплайн с Институтом** (слово Rudra 2026-10-13): Институт сам проводит
   исследования передовых технологий; только когда признаёт находку годной —
   передаёт её в Лабораторию на изолированную проверку. Лаборатория испытывает
   изолированно; в Мир входит только доказанное — с обоснованиями, в т.ч.
   рисками и альтернативами; после решения Rudra — передача в Инженерный Центр
   для внедрения.
5. **Приём и перенаправление интента:** интент в компетенции (испытание
   способности, изолированная проверка находки) — принимает; интент вне
   компетенции — перенаправляет релевантной локации через peer-comms с
   сохранением provenance (источник, исходный владелец, причина, статус), не дублируя владение; в один
   момент — один явный lead.
6. **Связь по peer-comms:** канал «на связи» (метод `peer-comms`,
   OpenCode-Vault). Общение ≠ авторизация: письмо соседу не создаёт задач
   и не даёт прав.
7. **Карантин лора:** имена лора (Ekstasis / Alexander Maya / Allis Maya,
   Вельдора) не переносятся в инженерные решения; живут в лор-треке.

## Что этот документ НЕ делает

- Не создаёт runtime, агентов, банка данных (банк данных — T-171, отдельная
  задача со своим одобрением) и не запускает испытания L1–L6.
- Не решает EEG/айтрекинг-инфраструктуру (аппаратные эксперименты — отдельные
  задачи с собственным одобрением).
- Не трогает frozen T-108/109/110 (мост и permission experiments).
- Не канонизирует лор и не переносит его в инфраструктуру.

## Порядок утверждения

  canon/approval gate.
- **Куда фиксируется:** карточка проекта dotfiles и/или route-log волта.

# T-124 Telemetry P0 (ECO-002) Спецификация

> Спецификация разработана в рамках задачи **T-124** (приоритет P1). Цель — реализовать лёгкие custom tools для сбора телеметрии токенов и аудит-лога с соблюдением требований конфиденциальности ( metadata-only, без логирования текста промптов/ответов).

## 1. Архитектура и требования
- **token-budget:** Инструмент мониторинга потребления токенов (запросно/сессионно), с отсечкой порогов и отчетами.
- **audit-log:** Аудит-лог выполненных действий/вызовов инструментов в формате JSONL (сохраняются таймстампы, ID задачи, имена инструментов и длительность, но **никогда** — содержимое промптов или персональные данные).
- **Интеграция:** Размещение в директории `.opencode/tools/` (в соответствии с конвенциями custom tools) или в качестве локальных утилит с возможностью вызова из сессий.

## 2. Формат данных
- Логи аудита пишутся в `control-plane/audit-log.jsonl` (append-only).
- Бюджет токенов хранится в структурированном виде для еженедельных отчетов (weekly report).

## 3. Границы приватности (обязательные)
- Логируются ТОЛЬКО метаданные: timestamp, task/session id, имя инструмента,
  длительность, счётчики токенов. Содержимое промптов, ответов модели,
  значения API-ключей и персональные данные НЕ логируются никогда.
- Перед записью применяется redaction-фильтр по ключевым паттернам
  (`sk-`, `Bearer `, `api_key`, `password`, `token=`).
- Лог `control-plane/audit-log.jsonl` — append-only; переписывание
  исторических записей запрещено.

## 4. Acceptance-критерии
- (a) Офлайн-тесты: fixture-based, без сети. Покрытие: redaction срабатывает
  на каждом паттерне из §3; append-only не портит существующие строки;
  корректный подсчёт токенов; поведение при отсутствии/битом логе.
- (b) Независимое доказательство отсутствия утечки: прогон с искусственным
  промптом, содержащим секретоподобную строку, → grep по `audit-log.jsonl`
  не находит ни промпт, ни секрет.
- (c) Инструменты read-only по отношению к конфигам: не пишут в
  `opencode.json*`, `~/.config/opencode/**`, `~/.local/share/**`.
- (d) Независимый verifier PASS до перевода ECO-002 в LIVE.
- (e) Weekly report строится из лога детерминированно (один и тот же лог →
  один и тот же отчёт).

## 5. Статус
`planned` — спецификация, реализации нет. Не заявлять готовность до
выполнения acceptance §4.

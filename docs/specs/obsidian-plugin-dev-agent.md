# Субагент obsidian-plugin-dev

## Зачем
Служителю Обсидиан нужен подрядчик на плагины Obsidian (TypeScript): писать,
переписывать, багфиксить в зоне волта. Решение по агенту — зона ИЦ (Р-016).

## Вердикт ИЦ: отдельный профиль (не расширение util-dev)
- Разный стек: util-dev — утилиты UX в dotfiles (dunst/rofi/макросы);
  плагины Обсидиан — TypeScript + Obsidian Plugin API + сборка npm/esbuild.
- Разная зона: плагины живут в волте (`~/Projects/OpenCode-Vault/.obsidian/plugins/**`)
  и песочнице; util-dev пишет в dotfiles.
- Изоляция защищает Корабль: доступ плагин-агента сужен до зоны плагинов,
  код приложений (dotfiles, dv-hub, tools) — read-only.
- Повторяемость: у Служителя мандат регулярный (Deck → плагины → автоматизация).

## Профиль прав
- Разрешено: правки в зоне плагинов и песочницы; чтение всего, что нужно для
  задачи; bash в форме allow + deny-list опасных (sudo/chmod/chown/force-push/
  reset --hard/clean/rm -rf/rm/npm publish/systemctl stop/disable/mask).
- Запрещено: код приложений Корабля (правка), секреты (чтение/печать/коммит),
  установка системных пакетов, task (оркестрация), публикация пакетов.
- Сеть: документация — да; API-ключи — нет.

## Манифест (для УАСа, схема 11+4)
- Имя: obsidian-plugin-dev. Роль: subagent-разработчик плагинов Обсидиан.
- Вызывающий: Служитель Обсидиан (primary волта). Источник полномочий: слово
  владельца 10-25 через Служителя, мандат ЦУ obsidian-plugin-agent-20261025.
- Зоны: `~/Projects/OpenCode-Vault/.obsidian/plugins/**`,
  `~/Projects/OpenCode-Vault-plugins-sandbox/**` (правка), остальное — чтение.
- Статус: proposed → active после манифеста УАСа и существования файла агента.

## Приёмка
- Файл агента парсится, permission проходит сторож `tools/agent-perms/check.py`.
- Служитель может вызвать `task(agent="obsidian-plugin-dev")` после рестарта
  сессии (агентский файл подхватывается новой сессией).
- Первая задача — пилотный плагин в песчнице с verdict'ом Служителя.

## Риски
- Модель модели пин (amd-radeon/DeepSeek-V4.1-Flash — зеркалит util-dev):
  если смена — фиксация через владельца, не молча.
- scope-creep: агент может захотеть «поправить заодно» — границы зоны
  и deny-list держат; нарушение = инцидент.

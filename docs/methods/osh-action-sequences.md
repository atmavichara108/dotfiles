# Связки действий ОШ ( distilled, проверено на квестах)

## 1. Почта первым (канон Р-028)

`ship-mail.sh inbox <sid>` — zero-й шаг каждого хода; обработал → `ack`.
Отправка — только `send` с адресом из peer-registry (INC-18). Реестр:
`04-Memory/peer-registry.md` волта. Ящик ОШ: `inbox/ses_e8b9ae95.../`.

## 2. Квест-пайплайн (приоритет 0)

Разведка (read-only) → план с вариантами → **один** вопрос-апрув владельцу →
исполнение самому (если быстрее без потери качества — принцип «оперативность»)
→ канареечная проверка/`verifier` → рапорт: ровно запрошенное + важное.
Чужое в дереве — не спрашивать, не трогать; свои — коммит в `task/*`.

## 3. Канарейка прав (точечное зондирование)

Полный рецепт — `docs/methods/canary-permission-probe.md`. Ключ: позитивный
И негативный контроль + evidence-файлы на диске; route через subagent своей
сессии, не через headless `run`.

## 4. Багфикс на лету

Симптом → repro (≥2 стабильных воспроизведения) → гипотезы → письмо
Мастерской Багфикс (`ses_eda56e1d...`) через ship-mail → workaround в той же
сессии → постфактум владельцу. Известное семейство tool-call-багов:
`subagent`-resume режет sessionID; headless `run` — ECONNRESET на tool-ходе.
Правило: ≤2 ретрая, дальше workaround, инцидент не стопорит сессию.

## 5. Канон-линия после ночного свитча ветки

Симптом: коммит канон-артефакта остался на старой `task/*`-ветке и выпал из
рабочего дерева → в живом каталоге агента артефакта нет. Реакция: проверить
`ls` реального пути; восстановить `git cherry-pick <свой коммит>` на активную
ветку; сообщить ЦУ (какая линия кормит main — решение ЦУ); в main не мержить
без слова.

## 6. Рапортность

Владельцу — только запрошенное + важное по текущим заданиям. Копии ЦУ/ иным —
только для регистрации (ship-mail, metadata-only). Секретов в каналах нет.

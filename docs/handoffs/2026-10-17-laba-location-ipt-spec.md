# Лаба — перерождение Ability Lab: монорепозиторий инструментов и локация-сессия сети

## Цель

Оформить перерождение Лабы: переход локации «Ability Lab / Лаборатория»
(спека 2026-10-13, approval Rudra, `docs/specs/done/ability-lab-location.md`)
в ведомство с собственным монорепозиторием инструментов. Мандат — Rudra
2026-10-15, ref: `triple-mandate-20261015`, трек 1; слово Rudra «спека Лабы —
давай, параллельно», апрув в корне канала по Р-009. Все положения уже решены
в реестре решений (Р-005, Р-007, Р-013, Р-014, Р-015): спека сводит их, ничего
не согласовывая заново. Не создаёт runtime, репозиторий, сессию, манифест.
`kind: task`, `status: proposed`: исполнение любых структур — только после
approval Rudra, этапами с гейтами.

## Монорепозиторий laba

- Один репозиторий всех инструментов Лабы — `laba`, путь `~/Projects/laba`.
  Инструменты — отдельными директориями: `laba/mail-hub/`, далее
  `laba/<инструмент>/`.
- Общие конвенции репо: specs, tests, evidence. У каждого инструмента: спека —
  в общем spec-home репо, тесты — при инструменте, evidence — доказательства
  приёмки (независимый verifier, коммит).
- Один spec-home на репо: `laba/docs/specs/` (конвенция `<repo>/docs/specs/`).
  Спеки инструментов Лабы живут там. Локационные спеки сети остаются в
  dotfiles; эта спека — `docs/specs/laba-location.md` в dotfiles.
- Репозиторий `laba` — real estate-часть гибрида A+B (Р-005): свои документы
  в своём репо-доме.
- **Первый житель — mail-hub.** Р-007 закрывает открытый вопрос handoff:
  целевой репозиторий — общий монорепозиторий `laba`; mail-hub — его первый
  инструмент. Ответственность и границы — по handoff: Лаба проектирует и
  делает PoC; Инженерный Центр внедряет в dotfiles после review/verifier и
  handoff; аккаунты, DNS, реальные ящики и отправка NVIDIA — только
  отдельным шагом с владельцем.

## Правило graduating

Дословно из Р-007: «правило graduating: интеграция→dotfiles после acceptance
или рост→отдельный репо». Операционно — принятый инструмент идёт по одной из
двух веток:

1. Интеграционный слой в dotfiles — после review/acceptance и отдельного
   handoff; внедряет Инженерный Центр (Р-015), Лаба в dotfiles не пишет.
2. Рост в отдельный репо — когда инструмент перерастает монорепозиторий.

## Границы владения

Пересмотр границ по итогам архитектурного контура (Р-007):

- Лаба не пишет в волт и dotfiles: файловые зоны других ведомств не
  расширяются; дом Лабы — репозиторий `laba`.
- Интеграция инструментов в dotfiles — только через handoff (после
  review/acceptance, по правилу graduating); внедряет Инженерный Центр.
- L9 (локальный индекс) остаётся у Лабы (Р-013); L8 заморожен (Р-013).
- Интерфейс с УАС — как с куратором агентского контура: стандарты манифестов,
  реестр манифестов (Р-014), проектирование primary («Док»).
- Пайплайн сети сохраняется (контракт §3): Институт → Лаба (изолированная
  проверка) → решение Rudra → Инженерный Центр. Интент вне компетенции
  перенаправляется релевантной локации с сохранением provenance; в один
  момент — один явный lead.
- Карантин лора: имена лора не переносятся в инженерные решения.

## Добросовестность (что эта спека НЕ делает)

- Не создаёт runtime, репозиторий, сессию, манифест, агентов.
- Переезд Лабы в новый репозиторий — отдельный этап после approval, со своими
  гейтами. Существующая работа Лабы (протоколы L8/L9, ветка
  `task/lab-l9-20261015` в dotfiles) этой спекой не перемещается; её судьба
  решается на этапе переезда отдельным scope.
- Компетенции других ведомств не расширяются; права и границы доступа
  существующих ведомств не ломаются.
- Mail-hub: создание аккаунтов, DNS, подключение реальных ящиков, отправка
  NVIDIA — только отдельным шагом с владельцем (handoff); эта спека их не
  разрешает.
- Детали, не покрытые реестром решений, спека не решает; решения за Rudra.

## Порядок утверждения и исполнения после approval

1. Спека проходит гейт reviewer, затем ЦУ, затем approval Rudra. В main не
   мержится до approval.
2. С момента approval: манифест ведомства Лабы обязателен (Р-014) — первый
   живой манифест сети; заполнение по схеме выжимки, запись в реестр
   манифестов через ЦУ (куратор — УАС).
3. Каждый структурный шаг — создание репозитория `~/Projects/laba`, перенос
   mail-hub, переезд работы Лабы — отдельный этап со своими гейтами
   (reviewer, ЦУ, Rudra); спека не разблокирует внедрение разом.
4. DoD: перенос этой спеки в `docs/specs/done/` — только после независимого
   verifier PASS и approval Rudra (канон переноса).

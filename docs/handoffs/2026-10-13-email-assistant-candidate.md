# Handoff: кандидат «Почтовый ассистент» → Vault Inbox

## Запрос Макса

Basis: quoted, 2026-10-13:

> «ещё важный кандидат в очередь - ассистент почты, уже есть сессия с наработками, даже кажется почту подключили или собирались начинать»

## Что найдено — только read-only

- В Vault есть `tools/email-capture/`: ручной Gmail/IMAP CLI, который
  классифицирует письма по интентам и дописывает их в idea-graph.
- Код, тесты и черновая спека вошли в Vault-коммит `a19e1e6` от 2026-10-11
  (18 файлов); спека `docs/specs/email-capture.md` всё ещё помечена `draft`.
- Session-log от 2026-10-08 говорит, что build S1..S7 тогда работал в фоне.
  Точный исходный session ID пока не восстановлен.
- В `tools/email-capture/.env` файла нет; есть только `.env.example`. Это не
  доказывает, что подключения нигде нет. Live IMAP не проверялся; credentials
  и содержимое ящика не читались.
- Существующий capture CLI — не то же самое, что полноценный почтовый ассистент
  с triage/summary/reply. Требуемое поведение пока неизвестно.

## Дополнение: итог read-only аудита

- Исследователь дочитал README/spec/session-log и проверил тестовые метаданные.
- `.env` и `.state/` отсутствуют; в idea-graph нет узлов с
  `provenance.source=email:gmail`. Session ID не найден; воспроизводимый контекст
  — session-log от 2026-10-08 и коммит `a19e1e6`.
- pytest cache: `lastfailed={}`; коллекция включает smoke-модули, которые
  пропускаются без `IMAP_USER`/`IMAP_PASS`. Сохранённого вывода pytest и exit
  code нет, поэтому это не выдаётся за подтверждённый PASS.
- `.venv/` и editable-install metadata есть, но это не доказывает live IMAP.
  Итог: **живое подключение и получение писем не подтверждены**; отсутствие
  `.env`, `.state` и `email:gmail` узлов даёт сильный косвенный вывод, не прямой
  runtime-log.
- Прямой SQL к базе сессий был заблокирован permissions; `snapshot/` и узкий
  server-log query остались непроверенными. Никакие письма и secret values не
  читались; IMAP smoke не запускался.

## Просьба к куратору Vault

Через обычный Vault `/inbox` добавить этот кандидат в `99-Inbox`, сохранив
цитату Макса дословно и сославшись на уже существующий `tools/email-capture/`.
Не заводить вторую карточку, если `/inbox` найдёт эквивалент; в таком случае
связать с существующей записью и вернуть её ID.

Предлагаемый следующий scope после принятия кандидата: решить, должен ли
ассистент расширять существующий capture CLI или быть отдельным workflow;
проверить прямые runtime-улики подключения отдельным ограниченным планом.
Не читать письма, не извлекать/показывать значения credentials и не запускать
live IMAP без отдельного approval Макса.

В этой сессии Vault не редактировался.

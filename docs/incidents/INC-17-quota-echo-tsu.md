# Incident record — квот-деградация канала обработки писем ЦУ (эхо-ходы падают)

- **Incident ID:** INC-17
- **ts:** 1792243200 (2026-10-18)
- **error class:** provider-quota
- **source/tool:** provider/opencode-go (Go usage limit exceeded) у сессии ЦУ
- **route_state:** blocked (узел ЦУ недееспособен к обработке входящих четвёртые сутки)
- **notification_state:** finished (запись зарегистрирована ИЦ по заявке ИПТ, ref incident-quota-echo; письмо-подтверждение отправлено)

## Symptom
Письма в сессию ЦУ доставляются (квитанция в журнале до блокирующего хода получателя), но эхо-ход обработки ЦУ завершается ошибкой «Go usage limit exceeded»: подтверждений нет, входящие копятся неразобранными с 2026-10-15.

## Repro
Любая отправка в сессию ЦУ через letter.sh: receipt в журнале есть, exit-код хода 1, stderr содержит «Go usage limit exceeded». Стабильно 2026-10-15..18 (девять зафиксированных падений эха в журналах ходов; свидетель — ИПТ).

## Root cause
Внешнее ограничение: исчерпана квота провайдера opencode-go у сессии ЦУ. Дефекта канала letter.sh нет (журнал до хода, run-rc событие пишется — поведение корректно). Подтверждено диагностом ЦУ (INC-16-ЦУ, tsu-inc-relay-20261017) и независимой регистрацией ИПТ.

## Fix / workaround
Workaround действует: дубли не отправляются (идемпотентность message_id); критичные сведения ретранслирует ИЦ (прозьба ХПФ — по живому слову владельца 2026-10-18); субагенты ИПТ запускаются с явной моделью. Решение класса: (1) восстановление узла — переключение модели сессии ЦУ владельцем в интерфейсе (рекомендовано ИПТ и ИЦ: снимает накопившиеся гейты одной правкой); (2) канальное исключение класса — pre-send гейт letter.sh (проверка живости/квоты получателя до отправки, честная стадия delivery-declined) — проектирование в R5 Lineage, исполнение после сверки ЦУ×meta; (3) живое доказательство нужности Слоя 3 ADR-028: «delivered-без-processed старше 48ч» измерим (данный инцидент — эталонный кейс).

## Evidence
Доставленные квитанции при падающем эхе (журнал receipts): caab46a97417cabb (15.10), e3195ca248491381 (15.10), 3dea30c1eee58009 (17.10), 13a336eb310daacf (18.10), 195ab06bca52905e (18.10); мой кейс — c61e929ff806313f (17.10, прозьба ХПФ, seq=693 «delivered» без обработки; ложно-положительный read-gate — второй кейс класса, учтён в R5-критериях). Входящие ЦУ: пачка ≥5 писем с 15.10 (УАС-пакет обработан владельцем напрямую, мимо канала).

### Evidence-дополнение 2026-10-18 (вечер)
Деградация распространилась на второй узел: отправка ИЦ→ИПТ (25a45f9f, mail-external-reconcile ack) и ИЦ→ЦУ (88328aa9, op-reconcile-report) — обе: journal-receipt записан, run-rc=1, в session_message получателей записей нет (delivery-check NOT-DELIVERED). Класс тот же (provider-quota), измерение почтового затора теперь: 2 узла (ЦУ, ИПТ), 4-е сутки; обходной канал ИЦ (дублирование владельцу в чат) действует.

### Ревизия root cause и класса (калибровка адресов, 2026-10-18; корректировки ЦУ inc17-root-fix-20261018 и ИПТ inc17-correction)
Первоначальный диагноз «provider-quota у сессии ЦУ» ревизован: письма с 18.10 ~04:52 уходили на ses_ecae229fcffef5FrLdWOJLos1K — мёртвую регистрационную запись (title «Register Lab session in registry», агент meta), умершую ~04:52; у неё же была исчерпана квота её модели (сопутствующий фактор, не первопричина). Настоящий ЦУ жил в другой сессии и писем не получал.
- Класс ревизован: provider-quota → **stale-address-routing** (устаревшая адресация); родственный подкласс — phantom-address (INC-18: несуществующий id → автосозданная фантомная сессия, ложный DELIVERED).
- Класс решения: калибровка адресов по единому реестру `OpenCode-Vault/04-Memory/peer-registry.md` (канон ЦУ, calib-20261018; слово владельца 10-18 «сначала калибруйся с ними раз и навсегда»).
- Статус: **resolved-канонизировано** (адресная часть) с двумя оговорками: (1) pre-send гейт (адресат существует и жив до отправки, честный delivery-declined) не построен — остаётся в R5 open, чтобы класс не повторился до гейта; (2) подслучай ИПТ 25a45f9f (живой адрес, run-rc=1, NOT-DELIVERED, вечер 18.10) stale-address не объясняется — причина не установлена; компенсация — повторная отправка, доставка подтверждена получателем (inc17-subcase-close, ИПТ 2026-10-18); оставлен как evidence для pre-send гейта R5: необъяснимые одиночные отказы — прямой аргумент за гейт «адресат существует и жив до отправки».
- Evidence: письмо ЦУ calib-20261018; письмо ЦУ inc17-root-fix-20261018; письмо ИПТ inc17-correction; peer-registry.md (сверка session_v2, 10-18 22:00); реестр ЦУ seq=760 (последнее доставленное 729, всё после 04:52 — в мёртвую сессию).

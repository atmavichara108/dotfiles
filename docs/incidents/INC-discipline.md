# Дисциплина инцидентов (мандат ЦУ 2026-10-26, ref `inc-discipline-mandate`)

Канон реестра `docs/incidents/`. Слово владельца (basis: quoted): «хватит
диагностики с нуля и костылей. Твой INC-реестр — оружие гомеостаза».

## Обязательные поля каждой записи

1. **class** — класс ошибки (адресация / доставка / permissions / провайдер / транспорт / парсер-схема …).
2. **root cause** — только из лога или сверки. Догадка помечается «не подтверждена»
   и не является корнем (INC-18 класс: «причина не установлена» — недопустим).
3. **fix** — что сделано, коммит/ссылка.
4. **evidence** — команда воспроизведения + вывод; не «проверил, работает».
5. **date** — ts + человеческая дата.

## Правило seen-before (перед любой диагностикой)

Перед новой диагностикой обязателен поиск по классу:
`rg -l "<class>" docs/incidents/`. Найденный ранее инцидент того же класса —
ссылка на него в новой записи в поле **seen-before**. Диагностика с нуля при
наличии seen-before — нарушение дисциплины (это дорого и плодит костыли).

## Классы, известные реестру (обновляется)

| Класс | Записи | Корневая рамка |
|---|---|---|
| address-error / false-positive-delivery | INC-18 | id без валидации; read-gate меряет не то |
| channel-loss / false-sent | INC-18, INC-21 | журнал пишет успех до прогона; rc глотается if-без-else |
| permissions-policies-missing-action | INC-20 | нет allow-строки в `policies` → инструмент скрыт целиком |
| provider-quota / provider-transport | INC-17, INC-26p | квота и разрывы транспорта провайдера (не permissions) |
| agent-definition-shadow | INC-20 | двойное определение агента (проект + глобал); эффективен один |

## Интеграция с watcher

Watcher (зона ИЦ) поднимает инцидент в реестр автоматически, с причиной из лога.
Запись создаётся этим каноном: класс ищется по таблице, seen-before подставляется,
пустые обязательные поля — сторож.

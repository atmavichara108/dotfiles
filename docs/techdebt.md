### TD-001: Формализовать взаимосвязь OpenCode TUI ↔ M Code Desktop
**Дата:** 2026-09-29
**Контекст:** Два клиента одной экосистемы: TUI v2 (сервис + `~/.config/opencode/`) и M Code Desktop (Electron-форк, `~/.config/mcode/`). Факты из `01-Reference/mcode-desktop` (волт).
**Общее (уже едино):** auth-store и подписка opencode-go; проектный `.opencode/` читается обоими как есть.
**Разошедшееся (долг):**
- раздельные деревья конфигов и ядер агентов;
- плагины продублированы копиями (`decision-queue-hook`, `session-flush` лежат и там, и там) — правка в одном клиенте не доезжает в другой, дрейф уже был;
- раздельные стореджи сессий/логов; mcode-only органы (ring of peers, worktree-изоляция субагентов) в TUI недоступны.
**Долг:** нет единого источника для общего слоя; каждый фикс проактивного контура придётся делать дважды и сверять вручную.
**Цена промедления:** тихий рассинхрон гардов (env-guard правит в TUI, а mcode ходит со старым) → ложное чувство защиты.
**Путь закрытия:** решить — либо stow-пакет `mcode-global` с симлинками общего слоя (как `opencode-global`), либо sync-hook сверки копий; зафиксировать ADR и покрыть проверкой дрейфа.
**Связано:** программа проактивности P0–P2 (mcode-паритет каждого контура).
